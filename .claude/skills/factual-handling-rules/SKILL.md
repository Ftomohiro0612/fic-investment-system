# factual-handling-rules（数値・事実の取り扱いルール）

FICの記事は数値の正確さが信頼性の核。このSkillは、過去に繰り返し起きた**数値・単位・年度・会計の取り違え**を防ぐ。
情報の出所・信頼度は [[source-hierarchy]]、表現・断定の強さは [[expression-strength-rules]]（このSkillは「数値そのものの扱い」を担い、語調は扱わない。3点セットで運用）。

---

## 使い方（いつ・どの役員が参照するか）

| 役員 | 参照する具体的タイミング | 省略してはいけない理由 |
|---|---|---|
| `researcher_company` / `researcher_industry` | ・PDF/IRから数値を抽出し pdf_summary / 投入パックに記録するとき<br>・単位・年度・会計基準・セグメント区分を確定するとき<br>・独自試算を渡すとき | 素材段階の単位/年度ミスは、writer・記事まで増幅して伝播し、検算コストが最大化する |
| `writer` | ・数値を本文/表/サマリー/FAQに**書く前と書いた直後**<br>・前年比/構成比/感応度を計算するとき<br>・会社開示値とFIC試算値を併記するとき | 単位×10ミスやセグメント推定は「ファクト事故」そのもの。記事の信頼性を直接破壊する |
| `reviewer` | ・公開前ゲートで、単位統一・年度対応・同一指標の数値揺れ・±50%変動の注記・推定の混入を**検算**するとき | 公開後の数値訂正は信頼性とSEO/GEOを毀損。**最後の防壁**で省略不可 |

> **ファクト規律は3段で各々invoke**（researcher予防 → writer確認 → reviewer最終ゲート）。数値は「抽出時の取り違え」「執筆時の計算ミス」「見落とし」が別々に起きるため、3段はそれぞれ別の事故を捕まえる防御層（フェーズ4 6-1）。

## 1. 単位の地雷（最頻出）

- **×10換算**: `billion yen / JPY B / 10億円` を「億円」に直すときは必ず**×10**。
  - 例: `1,128.6 billion yen = 1兆1,286億円`。`1,128.6億円` と書くのは**禁止**。
  - 兆円またぎも同じ: `10,586.7 billion yen = 10兆5,867億円`（`1兆5,867億円` にしない）。
  - **百万円↔十億円↔億円**: 百万円をそのまま「億円」と誤読しない（1億円=100百万円）。十億円単位は×10で億円。
  - **USD（億USD / million USD）には×10を適用しない**（`69億USD` を `690億USD` にする事故が頻出）。
  - 単位が確認できない場合は**原表記保持**（`130（単位要確認）`）。後で別箇所と揺らさない。
  - 単位系は文書内で**1つに固定**（`億円` と `10億円単位` を混在させない）。
- **率 / 額 / ポイントの区別**: `粗利率が47.2%→48.1%へ+0.9ポイント改善`（％≠ポイント）。`+Nポイント` は元の2数値から再計算して一致を確認。一致しなければ削除し `60%台半ばまで上昇` の丸めへ。
- **残差を純粋項目名にしない**: 売上総利益等から既知項目を引いた残額を、会社非開示の項目名（例: `キャピタルゲイン`）と断定しない。やむを得ず使うなら `残差参考値` `〜等` `定義要確認` を同じ文に。残差を1行サマリー・主要結論の中心数値にしない。

---

## 2. セグメント・構成比（推定禁止・主語・通期/四半期）

- **セグメント別利益の推定禁止**: 集計値（連結営業利益など）しか開示されていない場合、セグメント別の利益・利益率を**推定で割り付けない**。
  - 用途別・製品別売上だけ開示の企業は、公開本文で `セグメント別` と呼ばず `用途別売上構成` `製品別売上構成` と言い換え、表直下に `利益・利益率は会社非開示` と明記。
- **単純合算の禁止**: セグメント定義・消去調整・本社費用が未確認のまま「IM+BK合計で約3,000億円」のような単純合算を主文で断定しない。参考値として触れる場合は `単純合算参考値` `定義差の可能性あり` を同じ文に。主要セグメント合計が連結合計と概ね一致しない場合、`その他` `全社及び消去` `調整額` 行の欠落を疑う。
- **構成比の主語**: `全社売上構成比` `事業内構成比` `用途別構成比` `地域別構成比` は別概念。**主語を省略しない**。事業内構成比を全社構成比に勝手に拡大解釈しない。
- **通期と四半期の区別**: 通期実績／四半期単独／四半期累計／通期会社予想／進捗率は別概念。`4Q時点の構成比` を通期の地域売上比率として書かない。

---

## 3. 年度ラベルと会計基準

- **FY ⇔ ◯年◯月期 を1回だけ対応づけ、全文で使い回す**。
  - 3月決算で `FY25 = 2025年3月期` は**禁止**。正しくは `FY25 = 2025年度 = 2026年3月期`。
  - 12月決算は `FY25 = 2025年12月期`。**暦年と決算期を混同しない**。
  - `2024年度（25年度実績）` のような二重ラベル列見出しは禁止。「実績年度」「決算期」「会計基準」を別列に。
- **会計基準**: 中計のIFRS計画値を、直近実績もIFRS適用済みのように扱わない。日本基準実績とIFRS計画は列見出しで分け `単純比較不可` と注記。`金融費用除き税引前損益` `事業利益` `税前利益` を会社が明示しない限り `営業利益` と言い換えない。

---

## 4. 感応度の符号と結合

- 為替感応度は**資料の原文どおりに方向を保持**。「1円の円安で営業利益+40億円」を「1円のドル安で…」のように**符号反転させない**。
- 「円安/円高」と「ドル高/ドル安」を混在させない（何に対して1円動くのかを同じ文に）。原則 `1円の円安（対USD）で…` の形。
- 複数資料で感応度が異なる場合は `FY25 Q2資料では+29億円` `FY26会社予想では+40億円` と**時点・資料名付き**で整理し、無断で一本化しない。
- **結合感応度（原油+10ドルかつ為替+5円で+160億円）と単独感応度は別物**。資料に明示があるものだけ書く。1要素感応度を組み合わせた多要素シナリオは `会社開示ではなく試算` と明記。

---

## 5. 業績推移・YoY±50%注記・一時要因

- 過年度業績は取得できた最新年度から遡って3〜5期。**中間年度を欠落させない**。同じ表に確定値と参考値を混在させない。前提の異なる数値（単体/連結/国内のみ/参考値）を同じ列に並べない。
- **YoY±50%超の注記義務**: 純利益・営業利益が**前年比50%以上変動**している年度は、変動理由を資料内で調べて記載。説明がなければ `特殊要因含む可能性あり、有価証券報告書で要確認` と**1回だけ**注記。説明なしに大幅変動数値を並べない。
- **一時要因**: 利益率が大きく改善した場合、減損反動・事業譲渡益・金融収益・評価益などの一時要因有無を確認。確認できれば `一時要因を含む` `平常水準は要確認` を併記（強い形容での言い換えは [[expression-strength-rules]]）。
- 実績・会社予想・中計/Visionの比較表は**横軸を期間・縦軸を指標**にする。`項目/数値/注記` の縦持ちで期間名と指標名を混ぜない。

---

## 6. 会社開示値とFIC試算値の区別

- 粗利率影響・在庫月数・価格影響・上振れ/下振れの売上/営業利益など、会社が開示していない数値を出す場合は、必ず `会社開示値` / `外部推計` / `FIC前提付き試算（筆者試算/概算シナリオ）` のいずれかを**同じ文中**に明記。
- 試算には前提条件（対象売上比率・価格転嫁率・工期遅延率など）を添える。根拠が弱い数値は `小幅な下押し圧力` のような定性表現に弱める。
- 推計・参考値・残差・筆者試算を、1行サマリー・主要結論の中心数値に置かない。

---

## 7. 調査比率の分母注釈

- TDB・業界団体・調査会社の比率を使う場合、**分母と対象範囲を本文注釈**にする（`回答企業数` / `値上げ品目数` / `売上構成` / `コスト構成` のどれか）。
- 回答比率・要因比率・市場シェアを、総コスト比率のように読ませない。

---

## 8. 単位の別概念 / 金融会社

- `約35万社` `約35万拠点` `約11万社` `約110カ国` は**社数・拠点数・国数を別概念**として扱う。「拠点」と書かれた数値を「社」に書き換えない。揺れる場合は定義付き併記か `広い顧客基盤` に弱める。
- 金融会社（VC/PE/証券/銀行/保険/資産運用）は一般事業会社のPL用語に安易に置換しない。資料の主要表示（売上高/営業利益/経常利益/当期純利益）を優先。`売上総利益` は項目が明示され意味が確認できる場合のみ。

---

## 9. 出力直前の横断チェック（要点）

- FY と ◯年◯月期 の対応が全文一致しているか
- 単位（億円 / 10億円単位）が本文・表・箇条書き・シナリオ・注記で統一されているか
- 同一指標の別バージョン数値（`65%`と`66%`、`+7p`と`+10p`、`69億USD`と`8.7〜9.5億USD`）が混在していないか
- 為替感応度の `円安/円高` `ドル高/ドル安` の主語と方向が全文一貫しているか
- 50%以上変動の年度に一時要因または `要確認` 注記があるか

---

## 10. なぜこのルールがあるか（事故事例）

- **出光5019 単純合算/単位**: セグメントの単純合算や、原油処理能力 `93.1万バレル/日`（Make）vs `96.8万バレル/日`（一次）の食い違い。一次情報側を優先し、定義差・単位は注記で分離（`docs/claude_integrated_memo_lessons.md` §21）。
- **billion→億円の×10漏れ**: `1,128.6 billion yen` を `1,128.6億円` と書く事故。正しくは `1兆1,286億円`。
- **セグメント利益の過剰解釈**: 用途別売上だけ開示の企業で `セグメント別利益` と呼び、利益を割り付ける誤り。→ 集計値しか無い場合は推定せず `利益・利益率は会社非開示` と明記。
- **構成比の主語ずれ**: 「コンピューティング・通信向けが約90%」が `SoCテスタ内の用途構成` なのに全社売上構成と誤読する型（memo §7）。
  → いずれも「数値は資料にあるが、扱い方を誤る」事故。出所(source-hierarchy)・語調(expression)とは別の防御が要る。

## 11. セルフチェック（公開前 / レビュー時）

- [ ] 単位換算（billion→億円×10、百万円↔億円、USDは×10しない）にミスがないか
- [ ] 単位系（億円 / 10億円単位）が全文で統一されているか
- [ ] 率/額/ポイントを区別し、`+Nポイント` が2数値から再計算一致するか
- [ ] 集計値しか開示されていないのにセグメント別利益を推定していないか／単純合算を主文断定していないか
- [ ] 構成比の主語（全社/事業内/用途/地域）を省略していないか
- [ ] FY ⇔ ◯年◯月期 の対応が全文一致、暦年/決算期を混同していないか
- [ ] 感応度の符号・主語が原文どおりで、結合感応度と単独感応度を混ぜていないか
- [ ] YoY±50%超の年度に一時要因または `要確認` 注記があるか
- [ ] 会社開示値 / 外部推計 / FIC試算 の区別が同じ文中にあるか
- [ ] 調査比率に分母・対象範囲の注釈があるか
