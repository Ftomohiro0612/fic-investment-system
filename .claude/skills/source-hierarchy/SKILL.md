# source-hierarchy（出典階層ルール）

FIC投資研究所の編集方針の根幹は「一次情報優先・出典明記・未開示は未開示と書く」。
このSkillは、**情報の出所をどう評価し、どこまで公開記事の根拠に使ってよいか**を定める。
数値や断定の「強さ」は [[factual-handling-rules]]、表現・語調の強さは [[expression-strength-rules]] を参照（3点セットで運用）。

---

## 使い方（いつ・どの役員が参照するか）

このSkillは「読まれてこそ意味がある」。各役員は以下のトリガーで**必ず**参照する。

| 役員 | 参照する具体的タイミング | 省略してはいけない理由 |
|---|---|---|
| `researcher_company` / `researcher_industry` | ・各数値/主張/候補銘柄に出典を付けるとき<br>・品質階層表（業界13章パック §10相当）を埋めるとき<br>・パック完成前の自己点検 | 弱い出典を素材に混ぜると、後段が「強出典扱い」で本文化し事故が下流まで伝播する |
| `writer` | ・数値を本文/サマリー/FAQ/schemaに**書く前**<br>・URLを**引用する前**<br>・将来予測/市場規模を**書く前** | 中心根拠スロットに弱出典が入ると、記事全体のファクト強度が崩れ、修正コストが最大化する |
| `reviewer` | ・公開前ゲートで、弱出典の中心根拠化/曖昧な出典名/推測URL/鮮度切れ/地理的偏りを確認するとき | 公開後の訂正は信頼性とSEO/GEO評価を毀損する。**最後の防壁**であり省略不可 |
| `scout` / `theme_scout` | ・候補（銘柄/テーマ）の根拠ソースの質を評価し、A/B/C評価や採否を決めるとき | 弱い根拠で候補を上げると、下流の全工程が無駄になる |

> **ファクト規律は3段で各々invoke**（researcher予防 → writer確認 → reviewer最終ゲート）。
> 「前段が見たから省略」はしない。3段はそれぞれ別の観点（素材の質／本文化の可否／公開可否）でチェックする防御層であり、重複ではなく多段防御（フェーズ4 二重チェック 6-1）。

## 1. 出典の品質階層（強 / 中 / 弱）

| 階層 | 出典の種類 | 公開記事での扱い |
|---|---|---|
| **強** | 公式IR（決算短信・決算説明資料・有価証券報告書・統合報告書・中期経営計画）、公的統計（政府・中央銀行・取引所）、業界団体統計 | 中心根拠に使ってよい |
| **中** | 主要メディア（日経・Reuters・Bloomberg・FT）、大手会計/コンサル（Deloitte・PwC・EY・KPMG・McKinsey・BCG）、調査会社レポート | 補助根拠。使う場合は**時点・対象範囲・機関名を明記**。単独で中心結論を支えない |
| **弱** | 個人ブログ、SNS（Facebook・LinkedIn・Instagram・Substack・X）、投資SNS、暗号資産系ニュース、テーマ不一致ページ、未確認データベース、検索スニペットのみの情報 | **中心根拠にしない**。採用する場合も候補メモ（review_notes）へ。本文の主張を支えない |

### 1.1 「中」階層の中の注意（バイアス・二次資料・分母）

「中」は一括りにせず、以下は追加の注意を払う。

| 種類 | 扱い | 注意点 |
|---|---|---|
| アナリストレポート（証券会社発行） | 「中」より**一段弱め** | **買い推奨バイアス**に注意。目標株価・レーティングは**中心根拠にしない**。業界数値・前提など事実部分のみ補助利用 |
| 会社四季報・業界地図 | 「中」だが**二次資料** | 必ず一次資料（IR・決算短信）で**クロスチェック**してから使う。二次資料の数値を一次として断定しない |
| TDB等の調査比率 | 「中」 | **分母と対象範囲を必ず注釈**（回答比率／値上げ品目比率／総コスト比率／市場シェアの別を明示）。回答比率を総コスト比率のように読ませない（実装詳細は [[factual-handling-rules]]） |

## 2. 中心根拠ルール（弱い出典を主役にしない）

以下の「中心根拠」スロットには、原則 **強** を使う。**中** は時点・対象を添えて補助に。**弱** は不可。

- 1行サマリー / 30秒要約 / definition-lead / summary-box
- 「現在の水準」表の数値
- FAQ の回答数値
- Article / FAQPage schema の citation
- 主要結論・投資判断の中心数値

弱い出典の数値を summary-box・現在の水準表・FAQ・schema の中心根拠にしない（quality_checklist 該当項目）。

---

## 3. 出典名の書き方

- **「検索結果」「外部検索結果」「関連報道」を出典名にしない。** 必ず**実際の媒体名・機関名・統計名**で書く。
  - 例: `Reuters` / `日本経済新聞` / `国土交通省 新設住宅着工統計` / `日本製紙連合会` / `SEMI` / `RISI` / `Fastmarkets`。
- 実際の出典名が特定できない情報は、本文の根拠にせず「**出典不明のため不採用**」または内部メモへ。
- アナリスト・専門家コメントを引用するときは、**発表機関名・コメント主の所属/肩書・公表年月**を本文に併記。
  - 採用元は主要メディアまたは大手会計/コンサルのみ。個人ブログ・SNS・未確認DBは不可。
  - 最低1件は探し、見つからない/質が弱く不採用なら `該当なし/採用なし` と理由を明記。

---

## 4. URLの扱い（推測生成の禁止）

- URLは **input pack / スプレッドシート / WordPress検索結果 / 確認済みの既存FIC記事** から取得する。
- **URLを推測で生成しない。** 実在確認済みURLのみ本文・schema citation に使い、**確認日を併記**する。
- 未取得・未確認のURLは公開本文に残さない（`要確認` `リンク未取得` `URL要確認` を残さない）。必要なら「○○資料で確認する指標」として review_notes へ。

---

## 5. 将来情報・市場予測の出典強度

- 設備投資計画・新拠点計画・稼働予定時期・出荷能力拡大計画などの将来情報は、**会社一次資料で確認できた場合のみ断定**して書く。
- 会社一次資料で確認できない将来情報は `報道ベース` `第三者資料ベース` `会社資料で要確認` のいずれかを必ず付ける。
- 外部市場データ・CAGR・業界予測は `調査会社名 / 公表時点 / 予測対象年` をセットで残す。
- 検索スニペットの表現だけで「延期」「凍結」「停止」「撤退」「キャンセル」などの強い事象名に言い換えない（→ 語調は [[expression-strength-rules]]）。

---

## 6. 出典の鮮度ルール

- **強**出典でも、5年以上前のIR資料は「歴史的経緯・長期推移」用途のみ。最新実績・予想には**最新の決算短信/説明資料**を使い、古いスナップショット数値を最新実績として混在させない。
- **中**出典は**1年以内を推奨**。それ以上古い場合は時点注釈を必須化（例: `2024年時点`）。
- 業界統計は更新頻度（年次/四半期）を確認し、**最新版が出ているのに旧版を引用しない**。「現在の水準」として使う数値は、記事生成日時点で古すぎないこと。
- 古い資料を使う場合は `2025年時点` `中計策定時点` など**時点を同じ文・表に残す**。

---

## 7. 出典の地理的範囲ルール

- **日本企業分析**: 日本側公式に加え、海外側公式（相手企業のプレス等）が該当する場合は**並列確認**する。日本側のみだと、相手企業側の表現・用途範囲が抜け落ちやすい。
- **海外動向の引用**: 海外主要メディア（Reuters・Bloomberg・FT等）からも確認する。**国内メディアの孤立した翻訳記事のみに依拠しない**（孤立翻訳は弱め扱い）。
- 起点イベントには**最低3つの独立した中心ソース**を当てる。海外側が存在しないテーマは `海外側該当なし` と明記し、官公庁・業界団体・主要メディアの独立ソースを増やす。

---

## 8. 確度ラベルとの接続

出所（このSkill）と、事実の確度ラベルは対で使う。

- 区分ラベル: `公式発表` / `会社説明` / `報道ベース` / `調査会社予測` / `FIC仮説`。
- 混在する記事（新規事業発表・政策発表起点など）では、序盤に「区分 / 内容 / 投資判断上の意味」の3列表を置く。
- 数値の精度・断定の強さ（YoY±50%注記、セグメント推定禁止、単位地雷など）は [[factual-handling-rules]]。

---

## 9. なぜこのルールがあるか（事故事例）

- **出光5019（統合メモ照合）**: 外部メディア引用に**URLが付いていない**ものが多く、編集方針（一次情報優先）と不整合だった（`docs/claude_integrated_memo_lessons.md` §21）。
  → 教訓: 引用には必ず**実URL・媒体名・確認日**を付け、付けられないものは中心根拠にしない。
- **弱出典の中心根拠化**: 弱い出典を現在値表やschemaの中心根拠にすると、ファクト強度が崩れる。
  → 教訓: 中心根拠は強出典、弱出典は候補メモへ。
- **アナリスト目標株価の混入**: 証券会社レポートの目標株価/レーティングを本文の中心根拠にすると、買い推奨バイアスが記事の客観性を損なう。
  → 教訓: アナリストレポートは事実部分のみ補助利用、目標株価は中心根拠にしない。

## 10. セルフチェック（公開前 / レビュー時）

- [ ] 中心根拠スロット（サマリー・現在の水準表・FAQ・schema citation）の数値は、すべて「強」出典に裏付けられているか
- [ ] 「検索結果」「外部検索結果」「関連報道」など曖昧な出典名が残っていないか
- [ ] 推測URL・未確認URL・`要確認/リンク未取得` が本文に残っていないか
- [ ] 将来情報・市場予測に出典強度ラベル（会社一次資料/報道ベース/調査会社名+時点+対象年）が付いているか
- [ ] アナリストコメントに 機関名・所属/肩書・公表年月 が併記されているか
- [ ] **鮮度**: 中心根拠が5年超のIR・1年超の中出典に依存していないか（依存時は時点注釈があるか）。業界統計は最新版か
- [ ] **地理**: 日本企業の起点イベントで、海外側公式の並列確認（または `海外側該当なし`）があるか
- [ ] **バイアス**: アナリストレポートの目標株価/レーティングを中心根拠にしていないか。四季報/業界地図を一次資料でクロスチェックしたか

推奨grep（対象HTMLに対して）:

```bash
rg -n '検索結果|外部検索結果|関連報道|出典不明|要確認|リンク未取得|URL要確認' <article.html>
```
