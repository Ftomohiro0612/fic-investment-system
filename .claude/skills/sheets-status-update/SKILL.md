# sheets-status-update（Sheets俯瞰メタ更新）

工程をまたぐ進捗の**俯瞰メタ**は、スプレッドシート「**FIC記事管理_v3**」に集約する。
このSkillは、その**どのタブ・どの列に・どのステータス語彙で・どう書き込むか**を全役員で統一するためのもの。

役割分担（フェーズ3確定）:
- **handoff_*.md = 詳細な業務引き継ぎ**（完了内容・判断ログ・次工程への具体指示）→ [[handoff-templates]]。
- **Sheets = 俯瞰メタのみ**（ステータス・完了時刻・成果物パス・簡単な備考）。
- 両者をつなぐのが handoff 冒頭の「ステータスサマリ表」（＝Sheets同期項目）。Sheetだけ見れば進捗が分かり、handoffを開けば詳細が分かる二層構造（フェーズ4 6-4）。

---

## 使い方（いつ・誰が・どう書くか）

**完了時の必須アクション（全役員共通）**: 工程を終えたら必ず ①handoff_*.md 作成（[[handoff-templates]]）②**Sheets該当列を更新（このSkill）** ③reportに「handoff作成済み・Sheets更新済み」を明記。

更新は原則 `scripts/sheets/update_sheet_row.mjs` で行う（手編集はしない＝列文字ズレ・書式崩れ防止）。鍵を実行時に読み、**値はチャット/トランスクリプトに出さない**（A案の肝）。

## 3. 正式ステータス語彙（v3_ステータス定義 準拠）

正本は `v3_ステータス定義` タブ（2026-05-21 実読込み）。**書き込み時は必ず下記の文字列を一字一句コピー**する（表記ゆれはフィルタ・集計を壊す）。3区分があり、書く列が違う（§2）。

### 区分① v3運用（パイプライン全体ステータス＝状態ブロック AP-AS に書く）

| ステータス | 意味 | 次のアクション |
|---|---|---|
| 未処理 | Codex作業前 | 主要IR資料URLを確認 |
| Codex準備中 | PDF要約・補足検索中 | Codex作業を継続 |
| Claude投入待ち | Claude用パック作成済み | Claude.aiへ手動投入 |
| Claude出力待ち | Claudeで統合メモ・記事作成中 | 出力を戻す |
| GPTレビュー中 | Codex/GPTレビュー中 | 指摘を修正 |
| WP反映待ち | 修正後HTML確定済み | WordPress・シートへ反映 |
| 完了 | 記事作成から反映まで完了 | 画像・X・動画工程へ |

### 区分② レビュー（レビューブロック AF-AL に書く）

| ステータス | 意味 | 次のアクション |
|---|---|---|
| 未確認 | レビュー未実施 | レビュー実行 |
| 要修正 | 重要な指摘あり | 修正文を作成 |
| 修正済み | 指摘反映済み | 最終確認 |
| 問題なし | 公開品質 | WP反映へ |

### 区分③ チェック（個別ファクト/項目チェック）

| ステータス | 意味 | 次のアクション |
|---|---|---|
| OK | 確認済み | （なし） |
| 要確認 | 追加確認が必要 | 一次資料で確認 |
| NG | 修正必須 | 本文修正 |

> ⚠️ **語彙は旧Codex/GPT運用の名残**（「Codex準備中」「GPTレビュー中」「Claude投入待ち」＝手動Claude.ai投入前提）。新subagent体制では researcher_*/writer/reviewer が自動連携するため、語と実工程が一部ズレる。**ステータス文字列のリネームはFIC判断**（phase4 §6: AF/AG「GPTレビュー」列のリネームは任意）。リネームが入るまでは、新体制の工程を§3-1の対応表で最も近い既存ステータスに割り当てて運用する。

### 3-1. 新subagent体制 → v3運用ステータス 対応表

| 直近完了工程（役員） | 書く v3運用ステータス | レビュー列(AF-AL) | 補足 |
|---|---|---|---|
| researcher_company / researcher_industry | `Claude出力待ち` | — | 投入パック完成＝writerが記事作成へ |
| writer（記事3点完成・reviewerへ） | `GPTレビュー中` | `未確認` | レビューはClaude reviewerが担当（語は旧称） |
| reviewer（差し戻し） | `GPTレビュー中` | `要修正` | writerへ内部ループ |
| reviewer（修正反映確認） | `GPTレビュー中` | `修正済み` | 最終確認へ |
| reviewer（編集判断OK・designerへ） | `WP反映待ち` | `問題なし` | designerがWP反映 |
| designer（WP反映・画像完了） | `完了` | — | 画像・X・動画工程へ |

### 3-2. handoff状態（4値）→ v3運用ステータス の橋渡し

handoff冒頭の `状態`（4値: 完了 / 部分完了 / FIC確認待ち / エラー）は「**1回のhandoffという行為**」の状態。Sheets v3運用ステータスは「**案件全体のパイプライン位置**」。両者は別語彙（[[handoff-templates]] §6）だが、Sheets更新時に次の規則で整合させる:

| handoff状態 | Sheets側の扱い |
|---|---|
| 完了 | その工程の到達点に当たる v3運用ステータス（§3-1）へ前進させる |
| 部分完了 | ステータスは**前進させない**（現工程のまま）。チェック列に `要確認`、handoff §3に残作業を明記 |
| FIC確認待ち | ステータスは前進させない。チェック列に `要確認`、handoff §7にFIC判断事項を明記 |
| エラー | ステータスは前進させない。チェック列に `NG`、handoff §3/§7に原因と次アクション |

> 原則: **v3運用ステータスを「完了」やその先へ進めてよいのは handoff状態が「完了」のときだけ**。部分完了・FIC確認待ち・エラーのときは現ステータス据え置き＋チェック列で警告し、勝手に前進させない。

## 4. update_sheet_row.mjs の使い方

- 場所: `scripts/sheets/update_sheet_row.mjs`（リポジトリ追跡・共有資産。npm依存なし、`node:fs`/`node:crypto`/`node:path`＋組込みfetchのみ）。
- 認証: `getAccessToken(keyPath, scopes)` がサービスアカウント鍵（`.secrets/coastal-mercury-495123-k5-83baf0c72a93.json`）を実行時にfsで読み、RS256でJWT自前署名→access_token取得。**鍵の中身はコンテキストに載らない**。
- 主要関数: `getSheetTitles(sheetId, token)` でタブ名配列取得（対象タブ存在確認に流用）。
- **読み取り専用ヘルパ**: `scripts/sheets/read_sheet_tab.mjs`（同じ認証パターン・`spreadsheets.readonly` スコープ）。`--tab "v3_ステータス定義"`（任意で `--range "A1:D50"`）でタブのセル値をTSV出力。**ステータス語彙の最新確認・対象タブの列ヘッダ確認**に使う（書き込みなし）。

### モード

| モード | 動作 | 使う場面 |
|---|---|---|
| `--dry-run` | 認証＋タブ確認のみ（書き込みなし） | 書き込み前の接続/タブ存在確認（read確認に最適） |
| `--path-mode` | セルにパス文字列を書く | 俯瞰メタ運用＝このSkillの標準 |

### 標準手順（書き込み前に必ずdry-run）

1. **dry-run**で認証とタブ存在を確認（`--dry-run`）。タブ一覧に対象タブがあるか確認。
2. 対象タブ・行・列・値を確定（v3企業分析なら `--memo-col AB --article-col AD --date-col AA`）。
3. `--path-mode` で書き込み（成果物パス・ステータス・日時）。
4. 戻り値（更新セル範囲）を確認し、handoffの「Sheets同期列」欄に実際に更新した列を記載。

> 値はチャットに出さない原則のため、鍵パスや投稿ID等の機密はスクリプト引数・環境で渡し、ログに出力しない。

## 5. エラー時の対処

| 症状 | 想定原因 | 対処 |
|---|---|---|
| 認証失敗（401/invalid_grant） | 鍵パス誤り・鍵未配置・時刻ずれ | `.secrets/coastal-mercury-…json` の存在を existsSync で確認（中身は読まない）。dry-runで再試行 |
| 対象タブが見つからない | タブ未作成（pilot/候補タブ）・名称ゆれ | `getSheetTitles` 結果と照合。未作成ならFICに新設依頼（勝手に作らない） |
| 書き込み列がズレる | v3列と旧列順の取り違え | §2の列マッピングを再確認。v3は `--memo-col AB --article-col AD --date-col AA` |
| 権限エラー（403） | サービスアカウントが当該シート未共有 | FICにシート共有設定を依頼。**機密値はチャットに出さない** |

**判断に迷う/想定外のエラーは即停止しFICに相談**（フェーズ5原則）。本番タブの誤更新リスクがあるときは書き込まずに報告。

## 6. handoff との接続

- handoff冒頭の「ステータスサマリ表」の `状態`・`完了時刻`・`成果物パス`・`Sheets同期列` が、このSkillでの更新内容と一致するように書く（[[handoff-templates]] §3）。
- handoffの `状態`（4値）と Sheets正式ステータス（§3）は別語彙。両方を整合させる責任はこのSkillが持つ。
- 数値・出典・表現を伴うメタ（例: レビュー判定）を書くときは fact-safety 3規律（[[source-hierarchy]] / [[factual-handling-rules]] / [[expression-strength-rules]]）に照らした結果のみ反映する。
