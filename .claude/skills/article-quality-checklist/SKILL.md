# article-quality-checklist（公開前ゲート・最終防壁）

公開前に「**100点像を満たせているか**」を検査する最終ゲート。文体の作り方は [[writing-style]]、設計方針は [[article-design-principles]]、事実の安全は fact-safety 3規律が担う。本Skillは**統合判定**に絞り、各規律と重複する細目はそちらへ委譲する。

**上位**: [[article-design-principles]]（設計）
**実装元**: [[writing-style]]（文体）
**参照先**: [[source-hierarchy]] / [[factual-handling-rules]] / [[expression-strength-rules]]（事実の安全。細目はここで検算）
**章別の点検観点**: [chapter_design_guide.md](../../../docs/chat_workflows/_analysis/chapter_design_guide.md) を参照。

基盤: `prompts/shared/quality_checklist.md`（既存44項目）。本Skillは44項目を**基盤として継承**し、下記の新規/強化項目（B-0〜B-7）を加える。**現行適用は合計おおむね56〜60項目**。うちレイヤー/折りたたみ系（B-future）は**段階2以降に有効化**（γ）。現行標準＝公開15章・全章展開。

## 使い方（いつ・どの役員が参照するか）

| 役員 | 参照する具体的タイミング | 省略してはいけない理由 |
|---|---|---|
| `writer` | ・記事HTMLを書き終えた直後の自己チェック | 自己チェックで落とせば reviewer の手戻りが減る |
| `reviewer` | ・公開前ゲートで全項目をgrep含みで点検するとき | 公開後の修正は信頼性・SEO/GEOを毀損。**最後の防壁**で省略不可 |

> fact-safety 3規律は researcher→writer→reviewer の3段で各々invoke。本checklistは**最終統合ゲート**であり、各規律の自己チェックを置き換えない（重複検出は許容＝防御層）。

## A. 既存44項目（基盤・継承）

`prompts/shared/quality_checklist.md` の44項目をそのまま継承する。主な区分：
- 構成・骨格（結論先行／30秒要約／レイヤー／関連銘柄の一文接続／H2-1〜12のem導入＋「結局…」締め）
- 数値・引用（単位・出典・注記・調査比率の分母／会社開示・外部推計・FIC試算のラベル）
- 表現強度（公式より強い断定の有無／タイトルと本文の強度整合）
- WPメタ（`article_title:`/`slug:`／`<h1>`有無と `title.rendered` 検証／広い表の表示崩れ／未解決マーカー `要確認`等の排除）

→ これらは fact-safety 3規律と重複する項目を含む。**重複は委譲**（数値＝[[factual-handling-rules]]、表現＝[[expression-strength-rules]]、出所＝[[source-hierarchy]]）し、本ゲートでは「漏れの最終確認」として通す。

### B-6. 確認B由来（FICらしさ＝§8のchecklist化）
- [ ] **会計士視点**：一時要因と継続要因が区別されているか／設備投資・運転資本の将来収益への影響に言及があるか／会社説明と数値の動きの整合に触れているか。
- [ ] **上流→個別の主軸**：業界上流変数→当社KPI→営業利益の**波及チェーン（4〜6段）**が書かれ、市場全体の数字と個別業績の**中間要因**が明示されているか。
- [ ] **誠実な限界開示**：不明・仮説段階・一般傾向の**区別表記**があり、断定しきれない箇所に留保表現があるか。
- [ ] **時間軸**：価格転嫁・受注→売上計上の**ラグ**に言及し、一時収益 vs 継続収益の時間軸explainerがあるか。

## B-future（段階2以降・採用時のみ点検）

- [ ] **優先動線**：主要章＋冒頭だけで「投資仮説・確認ポイント・反証条件」に到達できるか。字数は削らず構造で速読動線を作っているか（補足章の深度を保持）。
- [ ] **レイヤー**：L1物理分離（ラベル・30秒要約・各章末「結局…」）。L2＝💡/📘・括弧言い換えが初出直後。L3＝補足章を `fic-detail-block`＋`<details>`＋視認ラベルで論理分離（物理3分割しない）。
- [ ] **補足のハイブリッド折りたたみ**：要約1行が折りたたみ外＝可視。本文は初期HTML直書き（JS後挿入禁止）。`<summary>`は内容を表す1行要約。

## C. セルフチェック（grep）

推奨grep（対象HTMLに対して）:

```bash
rg -n 'beginner-box|<details|<summary|業界判定|結局|要確認|要追加確認|TODO|FIXME' <article.html>
```

- 解説box（💡・📘とも beginner-box）の個数を数える（💡3〜7・📘3〜7・総計6〜14）
- `<details>` と各補足章の可視要約の対応を確認
- 「業界判定」「結局」の出現で定型句・章末締めを確認
- 未解決マーカー（要確認/TODO等）が残っていないか
