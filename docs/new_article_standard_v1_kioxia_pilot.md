## 2. ★横串の可視化（最重要）

**横串原則＝「投資仮説が崩れる条件（反証条件）を、記事のどの章でも同一KPI・同一閾値で一貫させる」。** 横串≠投資仮説。投資仮説（強気の核）と反証条件（崩れる引き金）は**同じKPIの表と裏**。

- **正本＝固定枠 disconfirming（反証条件①〜④）**。閾値はここを単一ソースにする。
- **§2に「投資仮説↔反証条件の表裏マップ」を新設**（強気の柱 ⇄ 反証①〜④をペア表示・番号付け）。これを正本ビューに。
- **§7（KPI）・§10（リスク）・見直しシグナルは、同じ①〜④・同じ閾値で“参照”**（言い換え禁止）。§7のbad_signは固定枠と**一字一致**（緩い言い換えにしない＝「横串が見えてこない」の主因）。
- 完全列挙は1〜2か所に絞り、他は短い参照に圧縮（"さっきも読んだ"疲労の解消と両立）。
- **監視KPIは反証条件①〜④に1対1で紐づける。浮いたKPIを作らない**。総合チェック（会社予想vs実績等）は「①〜④が崩れた結果」として最大1つだけ分離表示。

## 3. 非AIデータ図／構造図は「Astroチャートコンポーネント」（画像化しない）

- **非AIの図（セグメント/ウォーターフォール/表裏マップ/上流変数マップ/リスクマップ等）は `.astro` コンポーネント内にインラインSVG/HTMLを書き、MDXからimportして描画**（DOM展開＝機械可読・GEO有利）。配置例＝`kessan-yomu/src/components/charts/`。
- **やってはいけない**：(a) PNG等ラスタライズ＋`<img>`（旧WP方式）、(b) `.svg`ファイルを`<img src>`参照、(c) **MDX本文にraw `<svg>` 直書き**（HTMLブロック追跡を壊しbuild失敗）。
- **表より図表（マップ）**：横串・リスク等の"飛ばされたくない"要素は、普通の表でなく story-flow流儀の図表（結論帯＋カード＋⇄）にする。
- **AI概念図のみ画像**：上流環境マップ（単列フロー）／投資仮説マップ（2×2象限）＝AI生成PNG＝`<img>`でOK（非AI図とは別物）。
- 詳細＝[[kessan-yomu-hub-image-policy]]。

## 4. 編集の型（box・見出し・用語）

- **会計士の見立てbox（`.fic-insight`）**：FIC独自の考察・見立てを専用枠で際立たせる（💡/📘の初心者向けとは色・機能を区別）。事実と意見の区別は**boxラベル（🔍会計士の見立て）＋本文「会社は明示せず／本記事の見立て」で担保**し、末尾の過剰な但し書き（「あくまで推測で会社が断定していない」等）は**削る**。前置き（throat-clearing）も削り、見立てに直行。
- **見出しは平易な日本語**：噛む表現を避ける（×「何に期待して持つ会社か」→○「何を期待して投資するのか」）。8章は親しみある名前（「この先どこまで伸びる？ 将来の成長ビジョン」）。
- **専門略語は言い換え/📘**：英略語を説明なしで出さない（×「勝ち筋（KSF）」→○「勝ち筋（業界で勝つ条件）」）。writing-style 工夫1。

## 5. fact-safety（今回の確定事項）

- **指標名と数値を一致させる**：「売上総利益率」の行に営業利益率を載せない。**率は会社開示の構成要素から当研究所が算出**してよい（例：売上総利益1,012,904÷売上収益2,337,628＝43.3%「当研究所算出」）。営業利益率は「参考」と明示。四半期で会社非開示の指標は「会社非開示」と明示。
- **年度ラベル（◯年1月期／◯年3月期）は一次資料で裏取り**してから確定（決算短信/説明資料）。grep一致や社内メモの年ラベルを鵜呑みにしない（トリケミカルで1年ズレを検出・是正）。図には係争中の年を焼かない。
- 投資助言非該当（買い/売り/目標株価・PER割安断定なし）・免責を維持。

## 6. 出典の一本化（DRY・機械可読）

- **frontmatter `sources`（id/title/url/publisher/source_type/note）を単一ソース**にし、末尾の `SourceList`（「出典」）に**1回だけ**描画。**手書きの本文末「参照資料」ulは廃止**（重複・非機械可読のため）。確認日は `note` に入れる。
- **順序＝本文 → FAQ → 出典 → 免責 → 関連記事**（references last）。旧「参照→FAQ」より自然。
- **冒頭ヘッダ「主要出典」は1行圧縮**（主要1件＋「ほかN件 →」＝末尾 `#sources-title` へのアンカー）。フルリストを冒頭で再掲しない。
- fixed_frame/kpi の `source_refs` 整合のため、既存 id（例 kessan/tradersweb）は維持して拡充する。

## 7. 入口（description / リード / quick-answer / FAQ）

- **`description`＝結論先出しフック**（一覧カード・SEO meta・lead・llms.txt・RSS を駆動する単一ソース）。体言止めの構造説明にしない。titleと重複させない。例：「◯◯は△△で営業利益□□へ急拡大。利益の質は高いが続くかは××次第——A・B・C・Dの条件で読む」。
- **リード（タイトル下）＝結論要約**（quick-answerと整合）。事業構造式（ワンライナー）にしない。
- **ONE-LINER枠（事業構造式）は原則置かない**（description＝フック化でリードと役割が分かれ、3連サマリの重複を解消）。事業構造式はタイトル・本文に残す。
- **FAQは残す**（GEO/SEO・読後の振り返り）。各回答末尾に該当章へのアンカーリンク。設問は明瞭な日本語に（×「恩恵を受ける条件は何か」→○「追い風になるのはどんな時か」）。Rank Math FAQPage構造（H3=質問/p=回答）を維持。
