## 1. Phase 0標準チェック4項目の評価基準

`docs/lessons_3layer_pattern.md` §8-3 の4項目を、機械的に判定可能な評価基準として展開する。4項目は **「2軸×2軸」のマトリクス**で整理する：

|  | プロセス面（やったか） | 内容面（何を見たか） |
|---|---|---|
| 全体（既存資料一般） | **項目1**：所与扱いしていないか | **項目2**：Phase 5観点で再検証したか |
| 個別（特定要素） | **項目4**：権威性に依存せず変更判断したか | **項目3**：構造の実証データ判定したか |

### 1.1 Phase 5観点5次元（既存資料を点検する評価軸）

Phase 0完結（2026-05-24・commit 429ef19）で確立した5規律を、評価軸として展開：

| 次元 | 名称 | Phase 5標準 | 点検観点 |
|---|---|---|---|
| **D1** | 13章構成 | 13章（業界全体ロードマップ章新規独立・リスク章独立化・章9/10統合） | 既存資料の章構成と差分マッピング |
| **D2** | §2継承3点 | 起点イベント+確度4区分／N段階波及+業績反映ラグ／銘柄分類4区分 | 既存資料に各3点要素があるか／不足要素は何か |
| **D3** | B-10業界版5論点（役割分離） | FIC意見表出の質を点検する5論点 | 既存資料にFIC意見表出箇所があるか／控えすぎ箇所は何か |
| **D4** | L-028 4視点（§8-A/§8-B両併記） | 公式版＋FIC独自版両併記、4視点（隠れ/分解/実質比重/同業逆算）最低1点 | 既存資料が公式フレーム偏重か／独自視点の素材はあるか |
| **D5** | designer_industry 2系統化 | 影響経路マップ（確度ラベル視覚化）＋銘柄分類マップ（公式版/FIC独自版視覚区別） | 既存画像の構造と必要な視覚要素の差分 |

→ 企業分析パイプライン（researcher_company／writer／designer）の Phase 0標準チェックでは、上記D1〜D5の「業界版」を「企業版」に読み替えて適用（章構成＝公開15章構成／§2継承3点＝中心命題・ドライバー4本・同業比較核心／L-028 4視点＝企業版そのまま／designer＝1系統 等）。

### 1.2 4項目の評価基準（Pass/Fail判定）

#### 項目1：既存資料を所与扱いしていないか（プロセス×全体）
- **Pass条件**：既存資料の主要要素（章構成／銘柄分類／先行指標／確度ラベル／ドライバー視点）すべてに「採用／修正／削除／追加」の判定が記述されている
- **Fail条件**：既存資料の構造がそのまま継承され、再検討の痕跡がない
- **判定材料**：5次元それぞれについて再検討の痕跡を確認

#### 項目2：Phase 5観点で再検証したか（内容×全体）
- **Pass条件**：既存資料の重要要素すべてに Phase 5観点5次元（D1〜D5）のいずれかでの評価コメントが記述されている
- **Fail条件**：Phase 5観点での評価が言及されず、既存資料がそのまま採用されている
- **判定材料**：5次元での Phase 5観点コメントの記述網羅性

#### 項目3：構造の実証データ判定（内容×個別）
- **Pass条件**：構造的5次元（D1/D3/D4/D5）について、既存資料 vs Phase 5標準の差分マッピング表があり、各要素について「Phase 5標準に合致／変更が必要／追加が必要」の判定が実証データ付きで記述されている
- **Fail条件**：構造差分が言及されず、または実証データ抜きで「同じだから問題ない」と判定されている
- **判定材料**：差分マッピング表の有無＋各セルの実証データ

#### 項目4：権威性に依存せず必要な変更を加える判断（プロセス×個別）
- **Pass条件**：既存資料から変更が必要な要素について、「Phase 5観点でこう変える、なぜなら〜」という能動判断が記述されている。「動いている」「過去のFIC合意」を理由に変更を回避していない
- **Fail条件**：変更必要点が見つかっても「既存通り」と判断され、または変更理由が「Phase 5観点」でなく「Codex時代の慣性」になっている
- **判定材料**：主要変更項目の判断理由が Phase 5観点になっているか

## 2. handoff §4.0 テンプレ案

次工程への引き継ぎ handoff ファイル（`handoff_{from}_to_{to}.md`）に **§4.0 Phase 0標準チェック結果** を組み込むためのテンプレ：

```markdown
## §4.0 Phase 0標準チェック結果（L-029規律必須）

### 4.0.0 メタ情報
- 対象テーマ/銘柄：{key}
- 実施日：YYYY-MM-DD
- 実施者：{subagent名}
- 評価基準ドキュメント：docs/phase0_standard_check_framework.md
- 実証データ：work/{key}/phase0_standard_check_pilot.md（または同等）

### 4.0.1 対象既存資料一覧
| ファイル | 種別 | 作成元 | Phase 5での扱い |
|---|---|---|---|
| ... | ... | ... | 大幅再構築 / 再構築 / 書き直し / 継承 / 参照のみ / 歴史的参照に格下げ |

### 4.0.2 Phase 5観点5次元×既存資料 差分マッピング
- **D1（章構成）**：既存章数→Phase 5標準のセル別マッピング・所与扱いリスク判定
- **D2（§2継承3点）**：3要素の既存実装状況・差分判定
- **D3（B-10論点）**：FIC意見表出の質を5論点別に評価・所与扱いリスク判定
- **D4（L-028 4視点）**：§8-A公式版偏重か／§8-B独自版候補抽出
- **D5（designer 2系統化 ※業界版のみ）**：既存画像と Phase 5標準視覚要素の差分判定

### 4.0.3 4項目の総合判定
| 項目 | 判定（Pass/Fail） | 根拠 |
|---|---|---|
| 1. 既存資料を所与扱いしていないか | Pass / Fail | 5次元すべての再検討痕跡有無 |
| 2. Phase 5観点で再検証したか | Pass / Fail | 5次元すべてのPhase 5観点コメント記述網羅性 |
| 3. 構造の実証データ判定したか | Pass / Fail | 構造的次元の差分マッピング表+実証データ |
| 4. 権威性に依存せず変更判断したか | Pass / Fail | 主要変更項目の判断理由がPhase 5観点になっているか |

**総合判定**：全項目Pass / 部分Pass（要追加検討の項目あり）/ Fail（本作業着手不可・FICエスカレーション）

### 4.0.4 Phase 5観点で確定した変更項目（次工程申し送り）
[項目別の変更内容＋根拠＋次工程への申し送り。次工程subagentが起草時に必ず組み込む変更項目を網羅]

### 4.0.5 検証で発見された判断分岐ポイント（FIC壁打ち候補）
[実証中に subagent判断ではなくFIC判断委任が必要と判断した分岐点を記述。CLAUDE.md §3 原則1〜3]
```

### 2.1 テンプレ汎用構造の根拠

| テンプレ要素 | 汎用性 | 理由 |
|---|---|---|
| 4.0.1 対象既存資料一覧 | 高 | 任意のテーマ／subagentで既存資料リスト化可能 |
| 4.0.2 5次元差分マッピング | 高 | 5次元はPhase 0完結で確立した標準・全 subagent共通 |
| 4.0.3 4項目総合判定 | 高 | 4項目は L-029規律由来・全 subagent共通 |
| 4.0.4 確定変更項目 | 中 | テーマ固有の素材で項目数は変動 |
| 4.0.5 判断分岐ポイント | 高 | FIC壁打ち項目は全テーマで発生しうる |

## 5. L-029規律の効能パターン（実証蓄積中）

L-029規律（既存資料を所与扱いせずPhase 5観点で再検証）の運用効果は、複数の効能パターンとして発現する。実証データから抽出されたパターンを蓄積する：

| パターン | 発現条件 | 効能 | 実証例 |
|---|---|---|---|
| **パターン1：既存仕様への回帰** | 既存実装と既存仕様書が食い違っている | Phase 5変更の論理的裏付けが「既存仕様への回帰」で正当化される | sony-tsmc: 既存記事は3区分銘柄分類だが既存migration_spec は4区分定義 → Phase 5標準4区分への変更は「既存仕様への回帰」で正当化 |
| **パターン2：Phase 5観点欠如の発見** | 既存資料に Phase 5核心価値の構造が欠如 | MS2相当の実証ターゲット（FIC独自分析実証の理想ケース）を明確化 | sony-tsmc: D4（L-028 4視点）所与扱いリスク=最高 → 既存記事は素材あるが独自視点として打ち出されていない＝王子HD MS2前と同じパターン |

→ パターン3以降は残り5ロール展開時の実証で追補。
