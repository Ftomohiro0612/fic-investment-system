# Claude向け 業界分析記事作成 引き継ぎメモ

このメモは、Claude Codeが業界分析記事の流れを何も知らない状態から作業できるようにするための説明です。

## 目的

FIC投資研究所では、業界分析記事を以下の2段階で作成します。

1. **シナリオ1: 最近の業界テーマ候補を作る**
   - Codexが最新ニュースを調べ、記事化できそうなテーマをGoogle Sheetsの「業界分析」タブに追加する。
   - 候補はA/B/C評価で残し、削りすぎない。

2. **シナリオ2: 採用テーマを記事化する**
   - Codexが採用行を読み、追加調査・先行指標・因果チェーン・企業候補を整理してClaude投入パックを作る。
   - Claude Codeは投入パックをもとに、分析メモ・記事HTML・レビューメモを作る。
   - Codexがレビュー、必要修正、画像、WordPress反映を行う。

Claude Codeが担当するのは、主にシナリオ2の「分析メモ」「記事HTML」「レビューメモ」です。

## Claude Codeの役割

Claude Codeは次の3ファイルを作成してください。企業分析フローの3点セット運用と同じく、3ファイルを**1セットで作成**します。

1. `industry_analysis_memo.md`
   - 投資テーマの構造分析メモ。
   - 記事本文の前段になる素材。
   - 内部資料。

2. `industry_analysis_article.html`
   - WordPress投入用の記事本文。
   - 出力形式は `TITLE===`、`SLUG===`、`KEYWORDS===`、`BODY===<article>...</article>`。
   - 公開対象。

3. `industry_analysis_review_notes.md`
   - 自分で確認した注意点、弱い根拠、要Codex確認事項。
   - 公開本文ではなく内部メモ。
   - **省略禁止**。判断に迷った点がない場合も「迷った点なし」と明記した最小限のメモを残すこと。

### `industry_analysis_review_notes.md` の標準セクション

記事と統合メモには表れない裏側の判断を可視化し、後段のCodexレビューとFIC編集レビューを効率化するために、以下のセクションを構造化して残してください。

- ブラインドテスト宣言（参照したインプットの限定、参照しなかった既存記事・比較コメント等）
- 投入パック強化点と記事への反映状況（pdf_summary または input_pack の追加抽出項目がどう反映されたか）
- 判断に迷った点（Codex判断を仰ぐ箇所）
  - 用語表記の選択（業界用語のかな書き／英語表記など）
  - 利益指標の選択（複数指標が開示されている場合の採用）
  - 数値の出典差異（一次資料と報道で食い違う場合の採用判断）
  - 推定・仮説の使用判断（弱い出典を補助に使うか削るか）
  - シナリオ試算の本文使用判断
- 数値整合性チェック（主要数値と本文・表・FAQ・schemaでの一致確認、構成比合計、単位地雷チェック）
- 文章表現チェック（禁止表現、断定表現、強い比喩の有無）
- SEO/GEO・読み手チェック（タイトル、スラッグ、mark要素、beginner-box配置、FAQ構造）
- 画像挿入位置（画像コメントプレースホルダの位置、画像に入れる短い日本語ラベル、起点イベント、因果フロー、追い風、注意点、見る指標の候補語）
- 非AIグラフ・構造図の提案（図表名、挿入位置、使う数値、出典、読者に伝える一言、実装優先度）
- Codex公開前レビュー依頼項目（必須確認・任意確認・画像作成・WordPress掲載・シート更新）
- 完了サマリー（仕様書遵守状況、提示した論点数・確認項目数）

このメモは品質改善ループの起点として扱います。「Codex投入情報が薄い」「一次情報確認が必要」「別テーマでも再発しそう」と感じた項目は、後段の Codex が `docs/claude_industry_analysis_handoff.md` または `prompts/article/industry_analysis_*_main.md` へ反映できるよう具体的に書いてください。

### 役割境界（Claude / Codex）

Claudeは**統合メモ・記事HTML・レビューメモの3点セット作成**に専念し、Codexは**外部検索・投入パック作成・成果物レビュー・画像作成・画像挿入・WordPress反映・公開判断**を担います。

| 工程 | Claude | Codex |
|---|:---:|:---:|
| 検索・テーマ候補生成（シナリオ1） | — | ○ |
| `industry_analysis_input_pack.md` / `source_search_results.md` / `leading_indicators.md` 作成 | — | ○ |
| `industry_analysis_memo.md` 作成 | ○ | — |
| `industry_analysis_article.html` 作成 | ○ | — |
| `industry_analysis_review_notes.md` 作成 | ○ | — |
| シート反映（パス＋ステータス） | — | ○ |
| Claude成果物のレビュー（レビューメモ起点） | — | ○ |
| 画像作成・挿入 | — | ○ |
| WordPressへのアップロード・更新 | — | ○ |
| 公開判断 | — | ○ |

越境禁止: Claudeは画像作成・WP反映を行わない。Codexは記事文章の執筆を行わない（レビュー観点での修正指摘・数値差し替え依頼は可）。

画像方針: Codexは、Claude記事のレビュー後に生成AIで業界影響マップを作成します。Claudeは画像URLや未作成画像を推測せず、`industry_analysis_review_notes.md` に画像化すべき短い日本語ラベルだけを残してください。画像は「起点イベント → 因果フロー → 追い風/注意点 → 見る指標」が画像単体で分かる構成を標準にします。

非AIグラフ・構造図方針: 生成AI画像とは別に、数値比較・構成比・増減要因・時間軸・感応度を見せた方が読みやすい場合は、Claudeが図表案を提案し、Codexが実装・検証します。Claudeはグラフ画像を直接作らず、図表名、挿入位置、必要数値、出典、読者に伝える一言、優先度を `industry_analysis_review_notes.md` に残してください。「読者に伝える一言」は、抽象的な比喩や強すぎる断定ではなく、確認すべき指標や業績に効く段階が分かる実務的な文にしてください。

非AI構造図の見た目は、`docs/reference_images/industry_analysis/fic_non_ai_structure_chart_reference_01.png` と `fic_non_ai_structure_chart_reference_02.png` を参考にします。Claudeが依頼する場合は「AI生成ではなく、HTML/CSSで作る非AI構造図」「濃紺の結論見出し、黄色アクセント、太い日本語文字、4〜6要素、図だけで確認順が分かる」と明記してください。

### 品質改善ループ

`industry_analysis_review_notes.md` に残した「Codex入力で不足していた情報」「判断に迷った点」「一次情報で要確認の項目」は、Codexレビュー結果として以下の4分類で処理してください。

- `確認済み`: 一次情報で確認し、記事修正不要または修正済み
- `追加抽出済み`: 投入パックへ追加し、ClaudeまたはCodexで記事へ反映
- `記事側で再修正`: Claudeに再生成/修正を依頼する必要がある
- `据え置き`: 一次情報で確認できない、または記事に入れると過度な推測になるため採用しない

他テーマにも再利用できる項目は、`prompts/article/industry_analysis_memo_main.md` または `prompts/article/industry_analysis_article_main.md` へ反映する候補として `claude_review_notes` 末尾の「汎用プロンプトへ反映すべき事項」セクションに残してください。

## 絶対に守る運用ルール

### 1. 既存スラッグは変更しない

シートQ列または投入パックに「既存スラッグ」がある場合、`SLUG===` はその値を1文字も変更せず出力してください。

タイトルや本文を修正しても、スラッグは再生成しません。

既存スラッグが空欄のときだけ、新しい英語ハイフン区切りのスラッグを作ります。

### 3. 業界分析の見出しタイプを選ぶ

業界分析記事は、企業分析記事のように末尾へ大きな `関連銘柄分析` / `関連テーマ分析` ブロックを置く構成にしません。

見出しは記事タイプ別に選びます。

- 新規事業・ニュース解説型: `何が発表されたのか → なぜ重要なのか → 事業モデルと収益化 → 技術/仕組み → 数字で見るインパクト → 企業価値への影響 → 競争環境 → ボトルネック → 反対シナリオ → 投資家が見るべき指標 → まとめ → FAQ → 参照資料`
- マクロ・テーマ記事型: `トレンドの概要と発生要因 → 影響経路 → 恩恵セクター → 主要企業で見るべきポイント → 逆風セクター → ボトルネック → 先行指標 → 3シナリオ → 反対シナリオ → 投資家が見るべきポイント → まとめ → FAQ → 参照資料`
- 企業群・業界比較型: `業界の現在地 → 収益構造と業績ドライバー → 主要企業の比較 → 勝ち筋の違い → 先行指標 → 3シナリオ → リスク → 投資家が見るべきポイント → まとめ → FAQ → 参照資料`

row83のように、特定企業の新規事業発表を投資テーマとして読む記事は「新規事業・ニュース解説型」です。いきなり「トレンドの概要」「恩恵セクター」から始めず、まず「何が発表されたのか」を置いてください。

H2は短い章タイトルにしてください。原則15字以内、長くても20字程度に収めます。具体的な固有名詞・数値・比較軸はH3または本文冒頭へ移し、H2にコロン付きの長い説明文を入れないでください。長くなる章はH3で階層化してください。

`beginner-box` の見出し絵文字は削除しないでください。概念・誤読防止・因果の噛み砕きは `💡 ワンポイント解説：...`、業界難用語・会計難用語・業種固有KPIは `📘 用語メモ：...` とし、役割を見出しで区別します。Codexレビュー時もこの絵文字を落とさないでください。

起点企業のプロジェクト数値と、周辺企業・同業他社・市場全体の確認指標を同じ表に混ぜないでください。別プロジェクトや別会社の数値を同じ章で扱う場合は、H3と表を分け、表の直前に「これは起点プロジェクトそのものではなく周辺指標である」と分かる一文を入れてください。

関連銘柄は本文中の「企業価値への影響」「主要企業で見るべきポイント」「競争環境」に統合してください。関連テーマは「投資家が見るべきポイント」または「まとめ」で自然に触れてください。既存記事URLが入力に明示されている場合だけ、参照資料前に短い内部リンク欄を置いて構いません。

### 2. 既存WordPress投稿IDがある場合は新規作成前提にしない

シートAL列または投入パックに既存WordPress投稿IDがある場合、WordPress反映ではその投稿を更新します。

Claude側では新規URLや別スラッグを前提にした表現を作らないでください。

### 3. 発表主体・証券コードを必ず確認する

テーマ候補の企業例は暫定です。

row83のように、候補では「ソフトバンクグループ(9984)」と書かれていても、公式発表主体が「ソフトバンク株式会社(9434)」の場合があります。

記事では、発表主体・事業主体・親会社を分けて書いてください。

### 4. 因果関係を必ず厚くする

業界分析記事では、単なるニュース解説ではなく、以下の流れを必ず書いてください。

上流イベント
→ 業界内部メカニズム
→ 企業KPI
→ 売上・利益
→ 時間差
→ 反証条件

例:

AI計算需要増
→ データセンターの消費電力・瞬時負荷が増える
→ 受電容量、UPS、BESS、受変電、EMSが必要になる
→ 重電・電源システム企業の受注高や保守契約が増える
→ 売上計上は納入・工事進捗に遅れて出る
→ 部材費や工事人員不足が利益率の制約になる

### 5. 市場指標を個社業績へ直結させない

市場全体の需要やニュースを、個社の売上・利益にそのまま結び付けないでください。

必ず中間変数を挟みます。

例:

AIデータセンター増加
→ 電力設備容量の増加
→ UPS/BESS/変圧器の受注
→ 納入・工事進捗
→ 売上・利益

### 6. 読み飛ばされるKPI羅列を避ける

規模表やKPI表は、「何を判断するための数字か」が分かるものだけ残してください。

意味が伝わりにくい生産能力・販売量・設備数だけを冒頭に並べるのは避けます。

表は、読者が投資判断で使える横軸にしてください。

例:

- 現在
- 次期計画
- 中期目標
- 見るべき指標

### 7. 難用語は初出付近で説明する

業界難用語、会計難用語、業種固有KPIを2〜4語だけ選び、初出付近で短く説明してください。

「ワンポイント解説」とは別に、難用語向けの小ボックスとして置いて構いません。

例:

`BESS`、`UPS`、`EMS`、`受電容量`

### 8. 弱い出典は中心根拠にしない

本文、現在の水準表、FAQ、Article schema citationに使うURLは、投入パック内のリンク付き資料を優先してください。

URLを推測で作らないでください。

企業IR、公的統計、業界団体、主要メディアを優先します。

### 9. 記事本文では未完成表現を残さない

公開本文に以下のような表現を残さないでください。

- 不明
- 確認中
- 要確認
- 取得できず

必要な場合は「○○資料で確認する指標」として内部メモやレビューメモに回してください。

## 記事の基本構成

目安として、以下の構成にしてください。

1. 冒頭の短い答え

3. 起点イベント
4. なぜ業界に波及するのか
