# リポジトリ運用ルール

## 目的
このリポジトリを、運用しやすく、安全に変更でき、人にもコーディングエージェントにも分かりやすい状態で保つこと。

## 全体ルール
- 小さく、戻しやすい変更を優先する
- 何を変えたかだけでなく、なぜ変える必要があったかも残す
- プロンプトの正本は Make 直書きではなく、原則としてリポジトリ内ファイルで管理する
- 同じルールを複数のプロンプトに重複記載しすぎない

## プロンプト運用ルール
- 記事ロジックと SEO / GEO ルールは分けて管理する
- 導入、要約、出力形式はできるだけ独立して編集できる形にする
- 新しいプロンプトファイルは、再利用価値のある責務がある場合にだけ増やす

## WordPress 運用ルール
- スニペットを触る前に、対象テンプレートや表示箇所を明確にする
- 単発の投稿個別修正より、再利用できるスニペットを優先する
- 見た目は CSS、構造は PHP / テンプレートロジックで管理する

## SEO ルール
- 表現の見た目より、検索意図への一致を優先する
- 投資記事では結論を早めに出す
- 内部リンクは、次に読むべき記事へ自然に導く設計にする

## GEO ルール
- 分析の深さを落とさずに、AI や回答エンジンが抜き出しやすい構造にする
- 重要なエンティティ、業績ドライバー、投資家向け結論を早い段階で明示する
- 記事冒頭には、記事全体の直接回答として機能する短い結論ブロックを置く
- 分析根拠と参照資料の性質を、冒頭近くで分かるようにする
- 信頼性や抽出性が大きく上がるなら、見える形の「参照資料」セクションを置く
- 表示上の FAQ と schema 内の FAQ は一致させる
- 確認できた事実と推定値は明確に分ける
- 競合比較では、非開示項目が多い場合でも、確度の高い推定値・レンジ・代理指標で投資家に必要な相対感を示す
- 推定値は `推定`、`概算`、`方向感` と明記し、開示値と同じ精度の確定値として扱わない
- 推定の根拠が弱い場合は、実数比較ではなく `高・中・低`、`大きい・小さい`、`収益感応度の強弱` などの半定量表現にする

## ドキュメント運用ルール
- 優先順位が大きく変わったらロードマップを更新する
- 大きな構造変更や運用判断は change log に残す

## 引継ぎメモ（2026-04-26 時点）
- 企業分析フローでは、記事本文プロンプトは GitHub 読み込み運用、PDF要約と統合メモは Make 直書きの可能性があるため、変更時は GitHub 更新だけでなく Make 側反映要否も確認する
- 資料が複数ある場合、足元実績は最新の決算説明資料・決算短信を優先し、中期経営計画は目標値・戦略・起点数値として扱う
- 中期経営計画・統合報告書中心の入力では、過年度実績や四半期数値を無理に埋めず、戦略・KPI・事業構造を優先する
- PDF要約では、財務テーブルの行ラベルと数値、列見出しと年度対応を厳密に確認し、左右位置だけで前期・当期を判断しない
- PDF要約では、単体・連結・国内のみ・参考値など前提が異なる数値を同じ表で無理に混在させず、必要なら注記へ分離する
- IPO件数、M&A件数、株価、金利、為替などの指標は、市場範囲と時点を本文内で明記する
- 株価・金利・指数・為替は当日値でなくてもよいが、記事生成月と同月内の値を優先し、「2026年4月時点」「2026年4月下旬時点」などと明記する
- 投資会社・金融会社では、`売上高 / 営業利益 / 経常利益 / 当期純利益` を優先し、`売上総利益` の使用は一次資料の定義が明確な場合に限る
- 投資会社・金融会社の `収益構造ツリー` は、厳密な会計内訳ではなく `利益構造の見方` や `利益ドライバーの整理` として見せることを優先する
- `キャピタルゲイン`、`キャピタルゲイン等`、`残差` は混同せず、残差から推定した数値を純粋な収益項目として断定しない
- `管理報酬カバー率` のような指標は、分子・分母を必ず明示し、同一記事内で 31億円 / 32億円、86% / 89% のような揺れを残さない
- `AUM` という語は企業定義とずれることがあるため、必要なら `外部出資約束金額（以下、便宜的に外部AUM）` のように定義してから使う
- シナリオ分析では、市場全体の件数と会社固有の件数（例: 国内IPO件数と当該企業のIPO EXIT件数）を混同しない
- 記事冒頭は `1行サマリー → definition-lead → この記事の結論 → この記事でわかること → 分析根拠` の順が現在の標準
- 記事末尾には、参照資料セクションと FAQ / FAQ schema の整合を置く
- WordPress 側では、決算スケジュールカードの状態は `公開済み / 更新予定 / 記事作成予定` の3種類を基本とし、`本日決算` は使わない
