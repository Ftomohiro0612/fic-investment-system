# レビュー教訓ログ（review_lessons_log）

reviewer 差し戻し・点検で得た**再利用可能な教訓**を蓄積し、段階の節目に Skill／ガイド／チェックリストへ**curationのうえ蒸留反映**するための台帳。subagent は実行間の永続記憶を持たないため、writer を賢くする＝writerが毎回読む静的資産（Skill / chapter_design_guide / quality-checklist / writer.md）を更新することに等しい。本ログはその「反映待ち教訓のプール」。

## 運用ルール

- **追記専用**。reviewerの差し戻し・点検で出た「他の記事にも効く」教訓のみ記録（一回限り・企業固有で再利用性のないものは原則記録しない／記録する場合は普遍性=低と明記）。
- **生の差し戻しをそのままSkillに自動反映しない**（CLAUDE.md §7：`.claude/skills/` は段階・ステップ承認を経て更新）。本ログは反映の**手前**。1事例での昇格を避け、複数事例で普遍性を確認してから蒸留。
- **curation判定欄は段階4で記入**（採用／不採用／要追加観察）。段階4のSkill磨き込みでまとめて反映先を確定する。
- 各記事の指摘→対応の生履歴は `work/{key}/claude_review_notes.md ④節` が正本。本ログはそこから**横断教訓だけ**を抜き出したもの。

## 教訓昇格判定基準（即時反映 vs 段階4）

教訓を Skill/guide/template へ反映する判定基準（FIC合意 2026-05-22・C'案）。段階4 curation でも同じ基準で運用する。

- **即時反映してよい**＝**論理的に根拠づく原則** or **repo＋実物（公開HTML/一次資料）の両ソースで裏が取れた普遍ルール**（1事例でも昇格して安全）。
- **段階4へ送る**＝複数事例で初めて普遍性が見える**“データ的一般化”**（1事例では普遍か個社固有か判別できないもの）。
- **§7ゲート対象＝`.claude/skills/` 配下のみ**（Skill更新はFIC承認が必要）。`chapter_design_guide.md`・`wordpress/templates/`・本ログは§7対象外（FIC内容確認のうえ反映で可）。
- **判定例**：
  - L-005（反証＝観測パターン閾値）＝論理的原則 → **即時反映**（chapter_design_guide）。
  - L-006（予想範囲の明示）＝条件付き普遍ルール → **即時反映**（factual-handling §3＋template）。
  - L-008（文体基調＝です・ます）＝普遍ルール → **即時反映**（writing-style §5）。
  - L-002（IFRSラベル）＝両ソース裏取り済み普遍ルール → **即時反映**（factual-handling §3）。
  - L-007（ハイパースケーラCapEx）＝データ的・文脈依存、かつ既存の監視指標選定4基準（writing-style §9）で導出可能 → **新規Skill変更せず**（記事内のみ反映・段階4で「半導体固有か汎用か」を再検討）。
