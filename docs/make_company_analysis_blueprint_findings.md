# Make企業分析ブループリント読解メモ

作成日: 2026-05-14
対象: `企業分析_v5 (codex).backup-before-sensitivity-compare-fix.blueprint.json`

このメモは、Make時代の企業分析シナリオが何をしていたかをCodex/Claude Code運用へ移植するための読解メモ。

## 1. 全体フロー

Makeの企業分析フローは、おおむね以下の構成だった。

```text
Google Sheetsから対象行取得
→ FMPで企業基本情報取得
→ PDF.coで各IR PDFをテキスト化
→ ChatGPTでPDF要約を作成しシート更新
→ GPT①で外部検索キーワード生成
→ Serperで業界動向・リスク・競合を検索
→ Claudeで統合分析メモ作成
→ GPT②で統合メモから先行指標の最新値検索キーワード生成
→ Serperで先行指標の最新値を検索
→ GitHub上の記事生成プロンプトを取得
→ Claudeで記事本文作成
→ JSON parse
→ Google Sheets更新
→ 条件によりWordPress投稿
```

Codex/Claude Code運用では、Makeの自動実行をそのまま再現するより、以下の順に置き換える。

```text
PDF直読
→ pdf_summary.md
→ 業績ドライバー仮説
→ 先行指標・業界動向の検索
→ claude_input_pack.md
→ Claude Codeで統合分析メモ・記事本文
→ Codex/GPTでレビュー・シート反映
```

## 2. PDF要約プロンプトの思想

PDF要約は「短くまとめる」のではなく、後続の統合メモ・記事生成のために、数値と論点をなるべく保持する設計だった。

重視していた項目:

- 企業概要
- 主な事業
- 事業セグメント
- 各事業・製品の主要顧客、または顧客類型
- 売上高・売上構成
- 営業利益・主要利益指標
- KPI
- 成長戦略・中期経営計画
- 市場環境
- リスク
- 業績修正・ガイダンス更新
- 通期業績予想

重要な特徴:

- 極端に短い要約は禁止。
- PDFごとに、資料に書かれている内容だけを整理する。
- 決算説明資料は、最新実績・会社予想・セグメント数値を厚く取る。
- 中期経営計画・統合報告書は、戦略・目標KPI・顧客・事業構造・長期方針を厚く取る。
- 統合報告書にある古いスナップショット数値を、最新決算数値より優先しない。

Codex側への反映:

- `pdf_summary.md` は短縮版ではなく、数値保持型の資料別要約にする。
- セグメント別売上高、セグメント利益、物量、設備、ROE/ROIC、株主還元は漏らさない。
- 資料内にないものは「資料非開示」と明記する。

## 3. 数値事故防止ルール

Makeプロンプトは、過去の誤読をかなり強く意識していた。

特に重要な事故防止:

- 財務テーブルは行ラベルと列見出しを1対1で固定する。
- 売上高と売上総利益を混同しない。
- 前年・当年の左右を機械的に入れ替えない。
- 単体、連結、国内のみ、全体、参考値を混ぜない。
- FY、年度、決算期を会社の決算月から対応づける。
- 3月決算会社では、`2025年度 = 2025年4月-2026年3月 = 2026年3月期` のように扱う。
- 会計基準変更がある場合は、旧基準実績と新基準計画を無注記で比較しない。
- IFRS任意適用の開始期を推測で書かない。
- 通期、四半期単独、四半期時点構成比、現地通貨ベース伸び率を混同しない。
- 百万円、億円、10億円、billion yen、USDを混同しない。
- 会社非開示の内訳を残差から作らない。
- 推定値や残差参考値を記事の主文に置かない。

Codex側への反映:

- PDF直読後に、年度対応表・会計基準表を最初に作る。
- 単位は資料ごとに固定し、主要数値は表にする前に単位変換を確認する。
- 不確実な数値は記事に入れる前に「要確認」扱いへ落とす。

## 4. Serper検索の設計

MakeではSerper検索が2段階だった。

### GPT①: 業界動向・因果構造用キーワード生成

入力:

- 企業名
- 業種
- セクター
- PDF要約（決算説明資料、中期経営計画、統合報告書、その他資料）

目的:

- 売上の因果構造を分析するための外部情報を取得する。
- 最上流の需要動向、業界指標、市場規模予測、先行指標の傾向、リスク、競合比較を検索する。
- この段階では「現在の最新値」は検索しない。

出力:

- 8個程度の検索キーワードJSON配列。

Serper設定:

- endpoint: `https://google.serper.dev/search`
- `gl: jp`
- `hl: ja`
- `num: 3`
- `tbs: qdr:m6`
- `type: news`
- query: `<keyword> -filetype:pdf`

Codex側への反映:

- 統合メモ前のWeb補足では、まず「傾向・構造」を検索する。
- 最新値の検索と混ぜない。
- ニュース検索は直近6か月を基本とし、公式・一次情報を優先する。

### GPT②: 先行指標の最新値検索キーワード生成

入力:

- Claudeが作った統合分析メモ。

目的:

- 統合分析メモ内の先行指標から、外部から取得できるマクロ指標・市場指標のみを抽出。
- それぞれの最新値を検索するキーワードを5-8個作る。

対象:

- 政府・統計機関・市場データとして外部取得できるもの。
- 例: PMI、金利、為替、訪日客数、商品価格、市場規模、業界指標、建設費。

対象外:

- 会社の決算開示データ。
- AUM、棚卸資産、既存店売上、受注残など、PDFから取得済みの会社固有KPI。

Codex側への反映:

- Codex/Claude Code運用では、統合メモ前に先行指標を取ってよい。
- ただしMakeの設計思想を踏まえ、検索を2種類に分ける。
  - 業界動向・構造検索
  - 最新値検索
- 会社開示KPIはWebで検索し直さず、PDF要約を優先する。

## 5. Claude統合分析メモの思想

統合分析メモは記事本文ではなく、後続の記事生成のための分析素材。

目的:

- 企業紹介ではない。
- 投資家向けの売上ドライバー分析メモを作る。
- 最も重要なのは、売上と利益がどのような因果構造で動くか。

中心構造:

```text
最上流の需要
→ 業界指標
→ 企業の先行指標
→ 売上
→ 利益
```

必須方針:

- 因果構造は重要なものを2-4本示す。
- 一般論より企業固有の特徴を優先する。
- 数値、KPI、セグメント、成長要因、リスク要因を優先する。
- 記事タイトル、スラッグ、SEOキーワードは出さない。
- 注記は必要最小限。ただし重要な「不明」「資料非開示」「要確認」は残す。
- 各売上ドライバーについて「誰が投資・購買するのか」を必ず特定する。

Codex側への反映:

- `claude_input_pack.md` には、Claudeが因果構造を書きやすいように「業績ドライバー仮説」を先に書く。
- 会社固有の顧客・案件・顧客類型をPDFから抽出しておく。
- 統合メモに使わせたい表データを、Codex側で事前に整理する。

## 6. 記事本文生成の思想

記事生成プロンプトはGitHubから取得していた。

取得先:

`prompts/article/company_analysis_article_compiled.md`

記事の中心テーマ:

- 単なる企業紹介ではなく、「なぜこの企業の売上が動くのか」。
- 「原因 → 先行指標 → 売上」の流れを明確にする。
- 上流要因まで説明する。
- 定性的・定量的の両方を書く。
- 投資家が何を見ればよいか示す。
- 誰が買うか、誰が需要を生むかを書く。

記事で必須に近い表:

- 業績推移
- セグメント別売上構成比と主要顧客または顧客類型
- 地域別売上構成比（あれば）
- 売上の数式的分解
- 先行指標一覧
- 業績予測3シナリオ
- 同業他社比較
- リスク整理
- 売上または利益のツリー構造

重要な表現ルール:

- 会社開示で恒常的な主要顧客と確認できない企業名は「主要顧客」と断定しない。
- 個別案件由来の企業名は「案件例」「関連企業例」「代表案件」「需要の具体例」として扱う。
- 地政学・市況速報は強く断定しない。
- 原油価格、為替、金利、資源価格など時点で急変する数値は、時点と出典を明示する。
- 統合メモと検索結果が明示していない強い表現へ言い換えない。

Codex側への反映:

- Claudeに渡す前に、禁止表現・OK表現を企業ごとに作る。
- 外部ニュースは「最新値」「報道ベース」「一時的」などのラベルを付ける。
- 記事レビュー時は、顧客名の断定、市況速報の断定、単位、年度、会計基準を重点チェックする。

## 7. 今後のCodex作業への具体的な反映

次企業からの標準作業:

1. シートからPDF URLを取る。
2. PDFを直読し、`pdf_summary.md` を作る。
3. 年度対応表、会計基準、単位、セグメント売上・利益、ROE/ROIC、株主還元、物量・設備を確認する。
4. PDF内情報だけで業績ドライバー仮説を作る。
5. 業界動向・構造検索キーワードを作り、Web/Serper等で検索する。
6. 必要な最新先行指標をリスト化し、公式統計・市場データ・主要媒体で確認する。
7. `claude_input_pack.md` を作る。
8. Claude Codeに統合分析メモと記事本文を作らせる。
9. Codex/GPTがレビューする。
10. シートへパス、ステータス、レビュー結果、最終HTMLを反映する。

出光案件での改善点:

- Codex初回のPDF要約はMake要約より短く、セグメント売上高・物量・ROE/ROICなどの保持が弱かった。
- 今後はClaude作成の `docs/codex_company_analysis_pack_spec.md` と本メモを合わせて、PDF要約段階からMake並みの厚みを出す。
- 外部補足は、統合メモ前に取得してよいが、検索目的を「構造・傾向」と「最新値」に分ける。

## 8. セキュリティメモ

Makeブループリント内にはAPIキー等の機密値が含まれている場合がある。

- blueprintをGitHubへコミットしない。
- 共有前にAPIキー、Bearer token、Serper key、WordPress認証情報をマスクする。
- 既に外部共有した可能性があるキーはローテーションする。
- repoには `.env.example` のみ置き、実キーはローカルのsecret管理に置く。
