# AI画像（概念図）の見やすさ・運用メモ

**位置づけ**：データ図（数値グラフ）の見やすさは `data_figure_lessons.md` が、構造図／概念図一般の見やすさは `non_ai_structure_chart_lessons.md` が正本。本ファイルは**AI生成画像（概念図のうち designer が `ai_image_specs.md` 仕様で FIC手動Codex経由で生成する図）**の運用ルール（生成フロー・配置・パス管理・指示書の作り方）を扱う。
**初版**＝3861_oji_v4_pilot（designer・2026-05-24）で獲得（上流環境マップ＋投資仮説マップ）。今後の事例で追補する。

## AI画像生成フロー（designer §7・2フェーズ運用・L-011/L-012）

1. **フェーズ1（designer起草）**：designer が `ai_image_specs.md` を起草。各図につき、意図／伝えたい結論／プロンプト／配置章／注意点／**保存先絶対パス**／継承したドライバー定義を明示。
2. **FIC手動Codex生成**：FIC が `ai_image_specs.md` の該当セクションをコピーして Codex（AI画像生成機能）に貼り付け、PNG画像を生成。
3. **画像配置**：FIC が生成画像を**指定の絶対パス**に配置。
4. **designer通知**：FIC が designer に「完了」を伝える。
5. **フェーズ2（designer再開）**：designer が **画像存在確認 → 仕様準拠の自己検証 → プレースホルダ差し替え → handoff完了化** を実施。

## L-022：AI画像のFIC配置パス取り違え防止（2026-05-24）

**実例**：3861パイロットで、FICがAI画像を `work/company_analysis/3861_oji_v4_pilot/images/` ではなく `work/company_analysis/285A_kioxia_pilot/images/`（前回 designerパイロットのフォルダ）に誤配置していた。ファイル名は正しかったため designer の `find -name` 探索で即発見、コピーで正しいフォルダに配置・復旧。

**根本原因**：仕様書 `ai_image_specs.md` および「Codex送信用プロンプト」の保存先指示が**ファイル名のみ**（例「3861-oji-impact-map.png」）で、絶対パス（フォルダ）を明示していなかった。FICが前回 designerパイロットの感覚で `images/` に配置する際に、別の銘柄フォルダを選んでしまった。

**規律（次回から適用）**：

1. **`ai_image_specs.md` の保存先記述は絶対パスを明示**：
   - NG例：「保存先：3861-oji-impact-map.png」
   - OK例：「保存先：`work/company_analysis/{key}/images/3861-oji-impact-map.png`」または「保存先：`work/company_analysis/3861_oji_v4_pilot/images/3861-oji-impact-map.png`（絶対パス・銘柄フォルダを取り違えないこと）」

2. **Codex送信用プロンプトの末尾「FIC作業依頼」セクションにも絶対パスを明示**：
   - 「生成画像を `work/company_analysis/{key}/images/{filename}` に配置（フォルダ名の銘柄取り違え注意）」

3. **designer フェーズ2の最初のステップで画像存在確認**：
   - FICから「完了」指示を受けたら、まず `ls work/company_analysis/{key}/images/` または `find work/ -name "{filename}"` で AI画像の実在を確認。
   - 期待したフォルダに無ければ `find -name` で別フォルダにないか探索（取り違え発見）。
   - 見つかった場合は正しいフォルダにコピー（オリジナルは残し FIC判断で削除）。

4. **3層型反映**：
   - 層1：本書（`docs/ai_image_lessons.md`）の本セクション ✓
   - 層2：`review_lessons_log.md` L-022エントリ
   - 層3：`.claude/agents/designer.md` §7 フェーズ2 §5 に「画像存在確認」ステップ追加

## L-023：画像配置原則（章冒頭H2直下 or H3直下）— 2026-05-24

**実例**：3861パイロットで、designer が画像5点を全て**章末**（章1.3末・章2.3末・章5.3末・章6.1表直下・章7.1感応度節後）に配置していた。FIC実機確認で「画像があってそれを説明する文章が後に来る方が画像を存分に活用できる」と指摘され、テンプレ `wordpress/templates/company_analysis_template.html` のHTMLコメントも「**この章 or H3直下**」「**章冒頭 or ドライバー①直前**」と画像配置を明示していたことが判明＝**designerはテンプレ準拠でなかった**。

**規律（次回から適用）**：

1. **画像配置は「章冒頭H2直下」または「H3直下」を原則とする**。章末配置は読者の画像活用度を下げる。
2. **概念図（AI画像）＝章のメッセージ抽象化**＝**章冒頭（H2 + em導入文の直後）**が最適。読者がまず視覚で章のメッセージを把握→本文で深掘る流れ。
3. **データ図（SVG）＝本文の数値補完**＝**H3直下（表の前）**が最適。数値の視覚化を表より先に提供→表で詳細→本文で解説。
4. **冒頭テーブル＋全体図の組み合わせ**（例：章7冒頭の4列ドライバーテーブル＋感応度バー）は、**テーブル → 図 → H3** の順がよい（4本のドライバーを把握→感応度の符号で読み方を理解→個別ドライバーへ）。
5. **3層型反映**：
   - 層1：本書（`docs/ai_image_lessons.md`）＋ `data_figure_lessons.md` ＋ `non_ai_structure_chart_lessons.md` に同じ配置原則を追補。
   - 層2：`review_lessons_log.md` L-023エントリ。
   - 層3：`.claude/skills/article-design-principles/SKILL.md` §3-1テンプレに「画像配置は章冒頭H2直下 or H3直下」を明示＋ `.claude/agents/designer.md` ＋ `.claude/agents/writer.md` に画像配置原則を反映。

## ai_image_specs.md の作り方（標準テンプレ）

各図につき以下を明記（designer.md §7・L-022/L-023反映）：

```markdown
## 画像N：{図のタイトル}

### 出力ファイル名
work/company_analysis/{key}/images/{filename}.png（**絶対パス明示・銘柄フォルダ取り違え注意**・L-022）

### 配置章
{記事の挿入位置}。配置は**章冒頭H2直下** or **H3直下**を原則（L-023）。
- 概念図（AI画像）＝章冒頭H2直下
- データ図と組み合わせる場合のテーブル先後関係も明示

### 図で伝えたい結論（読者の持ち帰り）
{1〜2文で}

### 結論帯（最上部）
- メイン見出し：{15-25字}
- サブ見出し（黄色）：{中心命題＋数値}

### 構造仕様（3段カード／2×2象限 等）
{具体的な構造を明示}

### 矢印の指示
{読む順を矢印で固定する設計}

### 下部ラベル
読む順：{順}
次に確認すべき指標：{監視KPI}

### 出所注
{出典・確認日}

### スタイル指示
- 配色・フォント・カード幅
- AI画像は日本語テキストが崩れやすい → 文字数最小化
```

## AI画像の長所と短所（運用上の注意）

**長所**：
- 概念・質感の表現が得意（フロー・象限・カードレイアウト）
- 参考画像のスタイル準拠が可能（reference_images/）
- 大量の文字情報を視覚的に整理できる

**短所**：
- **日本語テキストが崩れやすい**（文字化け・誤字）→ 文字数を最小化＋figcaptionで補完
- **数値の正確性は保証されない**（再生成のたびに変わる可能性）→ 数値正確性が要る図はSVG／概念図はAI画像、と分担
- **参考画像の内容真似禁止（L-013）**：参考画像はスタイル（型・配色・質感）の見本。内容（会社名・数値・ドライバー定義）は王子HD固有として再指定が必須。

---

## 避けること
- **保存先フォルダ名の銘柄取り違え**（L-022）→ 絶対パス明示で防止。
- **配置を章末にしない**（L-023）→ 章冒頭 or H3直下が原則。
- **参考画像の内容真似**（L-013）→ スタイルのみ準拠、内容は当社固有。
- **画像内テキストに依存しすぎる**（AI画像は文字崩れリスク）→ figcaptionで補完。
