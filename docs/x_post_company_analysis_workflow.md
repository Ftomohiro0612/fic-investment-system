## 4. Codex移行後の運用

### 対象行

原則は次のどちらかで実行する。

- A列に「X投稿文を作成して」などの依頼がある行
- AT列が `未処理` の行

複数ある場合は、上から1件ずつ処理する。

### 入力HTMLの優先順位

X投稿文は、公開直前または公開済みの本文をもとに作る。

1. `AL: Codex修正後HTML`
2. `AX: 画像挿入済みHTML`
3. `AE: 記事本文`
4. GitHub/repo上の最終HTMLパスが列に入っている場合は、そのファイル本文

記事本文がファイルパスの場合は、ファイルを読んで本文として使う。

### URL

URLは次を使う。

```text
https://fic-investment.biz/{G列スラッグ}
```

スラッグは一度決めたら変更しない。

### 投稿案の作り方

Makeでは「4タイプ固定生成 → 人間が3つに絞る」運用だったが、Codex移行後は以下に変更する。

1. 記事本文を読み、Xでインプレッション・共感・クリックにつながりやすい切り口を考える
2. 記事の最重要論点を「初心者にもイメージできる言葉」に翻訳する
3. 決算記事・直近決算が主題の記事では、先に `AU: X投稿用 決算メモ` を作る
4. 固定型に縛られず、まず5案を試作する
5. 5案を比較し、最も良い3本だけを採用する
6. `AV: X投稿文章` には採用3本だけを保存する

試作時に使ってよい型の例:

- 逆説型: 一般認識を少しずらす
- 数字インパクト型: 強い数字を主役にする
- リスク・因果型: 下振れ要因と業績への波及を見せる
- 見落とし型: 投資家が見落としやすい論点を提示する
- 市場テーマ型: 原油、金利、AI、インバウンドなど話題性のある外部テーマと接続する
- 決算違和感型: 増収減益、利益率低下、会計基準差などの違和感を切り出す
- 中長期オプション型: まだ利益化していない成長テーマを、過度に煽らず見せる
- 比較型: 同業や過年度との違いを短く見せる
- 初心者翻訳型: 難しい論点を「つまり何を見る会社か」に言い換える
- ざっくり比喩型: 事業構造や利益構造を身近な言葉でイメージ化する

型は記事ごとに選ぶ。毎回同じ3タイプに固定しない。

### X投稿用 決算メモ

`AU` は、投稿文を作る前の素材整理欄として使う。ここにはX本文そのものではなく、今回決算の要約、ポジティブ要因、ネガティブ要因、次に見るべき焦点を短く置く。
2026-05-19以降は、単なる数字メモではなく、X投稿へ渡すための「初心者向け翻訳メモ」としても使う。

決算メモの目的:

- X投稿で使う論点と数字を先に固定する
- 投稿文生成時の数字誤り、論点重複、煽りすぎを防ぐ
- 投稿スケジュール作成時に、どの投稿が決算の何を切り出しているか確認できるようにする
- 難しい決算論点を、初心者にもイメージできる言葉へ先に翻訳する
- X投稿の温度感を「硬すぎる要約」でも「ネットスラング全振り」でもない位置に揃える

決算メモ作成プロンプト:

```text
企業分析記事本文、決算短信、決算説明資料、Codexレビュー済みメモをもとに、X投稿作成用の決算メモを作成してください。

目的は、X投稿本文を直接作ることではなく、投稿に使う数字・論点・温度感・初心者向けの言い換えを先に整理することです。
専門性は維持しつつ、Xで読まれるように「つまり何を見る会社か」「なぜこの数字が大事か」が一目で分かるメモにしてください。

以下の形式で、短く具体的にまとめてください。

【一言でいうと】
- この会社を今回どう見るべきかを、初心者にも分かる1文で書く
- 例: 「日本製紙は、紙の復活ではなく、紙の縮小を止血しながら生活関連と木材で利益を作り直せるかを見る会社」
- 例: 「トリケミカルは、AIブームそのものより、先端半導体で必要な材料が増える流れを見る会社」

【決算要約】
- 対象決算期、売上、営業利益、純利益、会社予想または次期見通しを、分かる範囲で整理する
- 一時要因、会計上の特殊要因、減損、構造改革費用、為替影響などがある場合は分けて書く
- 初心者向けに「売上は伸びたが利益率は下がった」「本業は堅調だが純利益は一時要因で減った」のように、読み方を1文添える

【ポジティブ】
- 利益を押し上げた事業、KPI、先行指標、構造変化を3-5点
- 数字が確認できるものは単位付きで書く
- それぞれ「なぜ投資家が見るべきか」を短く添える

【ネガティブ】
- 利益を押し下げた要因、リスク、次期の減益要因、未回復のKPIを3-5点
- 一過性リスクと構造リスクを混ぜない
- 怖がらせる表現ではなく、「何が確認できれば安心か」まで残す

【次に見る焦点】
- 次の四半期以降に確認すべきKPI、上流指標、会社計画とのズレを1-3点
- 「この数字が良ければ仮説が強まる / 悪ければ見直し」の形で書く

【Xで使える噛み砕き表現】
- 投稿に転用できる、やさしい言い換えを3-5本作る
- 1本40-80字程度
- 強いネットスラングは避ける
- 「ざっくり言うと」「つまり」「見るべきは〜」を使ってよい

【使わない方がよい表現】
- 誤解を招きやすい言い切り、煽り、記事本文より強い断定を2-4点書く
- 例: 「紙の会社だからオワコン」「必ず再評価」「買い」など

ルール:
- 記事本文または一次資料で確認できない数字は入れない
- 単位、対象期間、決算期を省略しない
- 投資判断の断定、買い煽り、過度な悲観表現は避ける
- X投稿に転用しやすいよう、1項目はなるべく1文で書く
- 専門用語は使ってよいが、初出では必要に応じて「つまり〜」で短く補足する
- メモ自体も読みやすさを重視し、長い文章で詰め込まない
```

### 選抜基準

5案から3本を選ぶ際は、以下を重視する。

- 冒頭でスクロールを止められるか
- 記事を読みたくなる余白があるか
- 数字または論点が十分に強いか
- 初心者でも「何の話か」がすぐ分かるか
- 専門用語だけで読者を置いていかないか
- 3本の切り口が重複していないか
- FICらしい「上流要因→企業KPI→業績」の因果が入っているか
- 煽りすぎ、投資助言、未確認情報の追加になっていないか
- X上で共感されやすい言葉になっているか

### 出力形式

`AV` 列には、採用した3本だけを見出し付きで保存する。

```text
【①〇〇型】
...

【②〇〇型】
...

【③〇〇型】
...
```

AT列には `完了` を入れる。

## 5. 品質ルール

Makeプロンプトの品質ルールを維持しつつ、固定型ではなく「5案生成→3案選抜」を優先する。

- 各投稿は200字以内
- 1投稿=1メッセージ
- 最初の15文字で「読んでみよう」と思わせる。違和感・疑問・親しみやすい言い換えのいずれかを使う
- 記事にない内容は足さない
- 数字は定義・単位・文脈が一致しているものだけ使う
- 単独数字の場合、「これ、同じ企業の数字か。」は禁止
- `#日本株` と会社名ハッシュタグを末尾に付ける
- URLを各投稿末尾に入れる
- 投資助言に見える断定、煽りすぎ、恐怖訴求は禁止
- 本文記事より少しカジュアルにしてよいが、強いネットスラングや銘柄を茶化す表現は避ける
- 難しい用語は、必要に応じて「つまり」「ざっくり言うと」で一言翻訳する

## 6. Codexで追加する確認

MakeからCodexへ移すことで、次を追加確認する。

- URLがスラッグと一致しているか
- 投稿文に未確認数値が混ざっていないか
- 採用3本が同じ論点の言い換えになっていないか
- 不採用2案より採用3案が明確に強いか
- 記事本文の重要論点（ドライバー、数字、リスク）が最低1本ずつ反映されているか
- 会社名ハッシュタグが長すぎる場合でも、原則は会社名を維持し、必要があれば人間レビューで調整する
- 画像作成済みの記事では、`AY: 画像格納フォルダ` にフルパスが入っているか

## 7. 今後の実装方針

Codex側にスクリプト化する場合は、以下の流れにする。

1. v3シートから `AT=未処理` またはA列依頼ありの行を取得
2. 企業名、記事タイトル、スラッグ、本文HTMLを取得
3. `prompts/social/x_post_company_analysis_main.md` のルールを適用
4. 記事ごとに5案を生成
5. 5案を比較し、インプレッション・共感・クリック率が高そうな3案を選抜
6. 文字数・URL・ハッシュタグ・未確認数値を簡易チェック
7. AU列に決算メモ、AV列に採用3本、AT列に `完了`、AQ/AS列に更新メモを書き戻す
