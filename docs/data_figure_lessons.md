# データ図（数値グラフ）の見やすさメモ

**位置づけ**：構造図／概念図（因果マップ・象限マップ）の見やすさは `non_ai_structure_chart_lessons.md` が正本（同ファイルは line16 で「正確な数値比較・比率は別の表・グラフで扱う」とデータ図を範囲外と明記）。本ファイルは**データ図（構成比・推移・ウォーターフォール等の数値グラフ）**の見やすさを扱う。designer が静的SVGで自力生成するデータ図に適用する。
**初版**＝285Aパイロット（designer・2026-05-22）で獲得（用途別売上構成・FY2023→25業績回復ウォーターフォール）。今後の事例で追補する。

## 構造図正本からの転用（データ図にも効く）
- 「この図で伝えたいこと（読者の持ち帰り結論）」を結論帯（濃紺＋黄サブ見出し）で先出しする。
- 要素を絞る／余白を広く／太字。
- 下部に「読む順／確認すべき指標」を一行で置く。
- 出所注（会社開示／外部推計／FIC試算）を図内に明記する。
- フォントは Yu Gothic／Meiryo／Noto Sans JP 系。

## データ図固有の見やすさ
- **グラフ種類は「伝えたい結論」で選ぶ**：構成比で「過半かどうか」を見せたいなら円グラフより**横100%積み上げ棒**が良い（小区分のラベルが潰れず、過半超えが一目で分かる）。
- **2段階で主因が違う推移**は、色分け＋凡例で表す（例：コスト要因＝グレー青／事業要因＝緑）。ウォーターフォールのブリッジで段階を分ける。
- **負の値（赤字）**はゼロ基準線を固定し、上下端を固定スケールにして赤字の深さを視覚化する。
- 凡例で「売上構成（利益・利益率ではない）」など、誤読しやすい主語を明記する。
- 正確な数値比較はデータ図側で担う（構造図は判断順序・因果を優先）。

## SVG実装の実務（WP埋込・JS不要）
- `<svg xmlns viewBox="0 0 W H" width height font-family="...">`。**font-family は CSS に依存させず svg 属性にベタ書き**する（WP環境のフォント差異対策）。
- 座標は px 手計算（ゼロ線・棒高さ・ブリッジの浮かせ位置）。**px／単位の換算係数を図注やコメントにメモ**しておくと、値変更時の再計算が楽。
- **静的SVG**を使う（Chart.js／Mermaid は使わない＝WPでJS依存を増やさない）。
- 文字は実テキスト（`<text>`）で持つ。AI画像は日本語テキストが崩れやすいため、**数値正確性が要る図はSVG／概念・質感が要る図はAI画像**、と分担する。
- **特殊文字を必ずエスケープ**：テキストにも**属性（`aria-label` 等）にも** `&`→`&amp;`／`<`→`&lt;`／`>`→`&gt;`。**1箇所でも裸の `&` があるとXML全体が不正**になり、`<img src=.svg>` でも画像が出ない（WP配信のブロッカー）。「SSD & Storage」等で頻発（285Aで実際にaria-labelの`&`が原因でXMLエラー）。
- **単体XMLとして検証する**：HTMLにインライン埋め込みでの目視はNG（HTMLは`&`に寛容で見逃す）。**ブラウザで単体 `.svg` を開く／`<img src=.svg>` で読む**（厳密XML）で必ず検証する。

## 避けること
- 円グラフで小区分のラベルが潰れる（横棒へ）。
- 数値で因果段階を結ぶ（会社が感応度を非開示なら方向のみ）。
- 図の数値が記事本文・`pdf_summary.md` と食い違う（必ず一致させる）。
- 利益と売上の構成比を混同させる凡例。
- テキスト・ラベルが**viewBox幅や隣接バーを超えて見切れる／重なる**（折返し・短縮・バー外配置・viewBox拡張で回避。隣接バーとの重なりはバー幅・描画順で解消）。

## 追補：下部レイアウト見切れ防止（L-021・2026-05-24 3861縦ライン検証 FIC実機発見）

3861パイロットでFIC実機確認時に**SVG#1〜#3全てに同じパターン**の下部レイアウト問題が出た（L-016二層QA②の効果）。次回から仕組みで防ぐルール：

- **注釈枠（オレンジ枠等）の幅は「中の文字の実描画幅 + 左右各30pxの余白」を確保**する。フォント11pxの日本語は全角1文字≒13px、半角1文字≒7pxで概算（「〜」「★」等のCJK punctuationも全角扱い）。テキスト確定後に必ず幅を逆算する。
- **viewBoxの高さは「下部要素の累積高さ＋上下20pxマージン」で設定**。下部要素＝注釈枠（高さ40-55px）＋X軸キャプション（行間20px）＋下部ラベル3行（各20px間隔）。注釈の文字を増やす場合は viewBox を必ず再計算（700→760px等）。
- **下部テキスト同士の重なり防止**：X軸キャプション（「営業利益への効き方（億円）」等）と下部ラベル（読む順・出所）は**同一y座標に配置しない**。最低15-20pxの間隔を確保し、独立した行に置く。**3861のSVG#3初版でX軸キャプション y=675 と読む順 y=678 が重なり**FIC実機で発見＝今後は座標計画段階で重複チェック必須。
- **下部ラベルは2-3行に分割**：「読む順」「想定為替」「出所」など複数情報を1行に詰め込まない。各情報は独立した y 座標で1行ずつ配置。

## 追補：略語禁止（L-021・2026-05-24）

- **凡例・注釈・表記は略語を使わない**。「営業」「純」「経常」のような略語は**読者誤読のもと**＝何のことか即座に分からない。「営業利益」「純利益」「経常利益」と正式表記する。
- **3861のSVG#1初版**で注釈枠に「営業 △48.9% vs 純 +20.4%」と書いたところ、FICから「何のことか分からない・営業利益・純利益と書くべき」と指摘。今後は略語使用を発見したら必ず正式表記に置換する。

## 追補：感応度バーの符号表記一貫性（L-021・2026-05-24）

- **会社開示の符号明示がある項目**：「+」「−」を正確に記載（例：パルプ +34.3億／チップ −46.4億／USD/JPY −7.4億）。
- **会社開示の符号明示がない項目（原料側等）**：本文または図の凡例で「コスト面で減益方向と解す」等の解釈を**1回明示**したうえで、図上は「**−**」表記＋グレー色（凡例で「会社開示の符号明示なし（原料側・コスト面で減益方向と解す）」と説明）として一貫させる。
- **「±」表記の使用条件**：方向が両側にありうる場合のみ（実需給で対称な変動が起こりうる場合）。原料側で「上がればコスト増＝減益」と単方向の場合は**「±」を使わず「−」で統一**（読者は「±」を見ると「両方向ある」と誤読する）。**3861のSVG#3初版**で古紙・石炭・原油を「±X.X億」と表記しグラフはマイナス方向に描いたため、FICから「±なのにマイナスだけ？意味不明」と指摘＝今後は単方向は「−」で統一。

## 追補：データ図の自己検証は「ブラウザでの実描画」が必須（L-021・2026-05-24）

- subagentがSVGを生成した後、**HTML埋込のインラインプレビューでは下部レイアウトの見切れ・テキスト重なり・viewBox外のはみ出しが見えない**（HTMLは寛容＝表示できないものも表示しようとする）。
- ファイル内容のgrepでは検出不可（`&` エスケープは検出できるが、座標重なりは無理）。
- **L-016「二層QA」をデータ図単体にも適用**：designer はフェーズ1完了の **前** に、各SVGを単体で `<img src=.svg>` または直接ブラウザで開いて**実描画確認**してから handoff に進む。3861パイロットではこれをスキップしたため、SVG#1〜#3全てに見切れ・重なり問題が残存しFIC実機確認で発見された。**designer工程に「SVGブラウザ自己検証」ステップを正式組み込み（designer.md §7への追記＝FIC承認待ち提案）**。

## 追補：画像配置原則（L-023・2026-05-24 3861縦ライン検証 FIC実機発見）

データ図の配置は次の原則に従う（詳細＋AI画像の配置原則は `docs/ai_image_lessons.md` L-023に集約）：

- **データ図（SVG）の配置は「H3直下（表の前）」を原則**とする。表の前に視覚化を提供→表で詳細→本文で解説、の流れが画像活用度を最大化。
- **章末配置は読者の画像活用度を下げる**（FIC実機発見・3861パイロットで5図全てを章末配置していたが、テンプレ `wordpress/templates/company_analysis_template.html` のHTMLコメントは「H3直下・章冒頭」を想定していた＝テンプレ非準拠）。
- **冒頭テーブルと全体図の組み合わせ**（例：章7冒頭の4列ドライバーテーブル＋感応度バー）は、**テーブル → 図 → H3** の順がよい（全体把握→読み方理解→個別へ）。
- 詳細は `docs/ai_image_lessons.md`「L-023：画像配置原則」を参照。
